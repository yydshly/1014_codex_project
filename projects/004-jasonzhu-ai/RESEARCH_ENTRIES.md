# 004 · 需求研究网站入口

入口与公开访问记录整理日期：2026-10-15；使用方式更新日期：2026-10-17。用途、筛选顺序与检索式为本项目原创研究建议；平台功能与访问情况依据下方官方说明和 2026-10-15 的公开读取。未复制平台代码或配图。

从网络上的实际求助、使用反馈与工作任务发现线索，再回原文理解人、任务、障碍和已有办法。产品发现入口用于比较方案，热度与发布介绍本身不足以证实需求。

## 使用顺序

已有方向时，可以直接在 `#research` 输入并点击“开始研究”，由本机已登录的 Codex 执行公开搜索、原文读取、分析和筛选，再自动保存到发现库。每轮保留来源与读取状态、排除理由及下一步；模型摘要不等同于已核实事实。运行条件与实测见 [Web 说明](web/README.md)。下面是手动探索入口的方式，适用于还没有方向或需要自行扩展来源时。

1. 在统一研究入口 `#directory` 选择“先随便探索 / 找真实问题 / 找开源项目 / 找 AI 产品”。没有任务词时，按推荐网站与三步引导直接浏览，不必先限定自己的职业。
2. 按社区求助、产品反馈、付费任务或现有方案，以及语言和用途进一步筛选。读到具体问题或产品时，再决定要追哪条线索。
3. 可选填写观察人群，填写中英文任务词并更新检索式；也可以把任务词换成已知产品名。切换开始方式保留已填词；示例任务只在点击时填入。
4. 有对应语言的任务词后，选择 Bing 或 Google，打开搜索或复制检索式；没有任务词时仍可直接访问网站入口。
5. 读原文、回复和最新状态，在 `#discoveries` 保存具体发现：选择需求线索、GitHub 项目或 AI 产品，填写标题与具体链接，再记录原文摘录、自己的理解和下一步。来源与摘录可留空，未确认的信息明确保留为待研究。
6. 用“待研究 / 研究中 / 已整理 / 暂缓”记录进展，通过关键词、类型和状态找回材料。后续可编辑，误删可从回收站恢复；JSON 用于备份与合并导入，Markdown 导出未删除记录，便于继续交给 AI 研究。
7. 要继续扩大搜索时，将入口或已保存的发现带入采集计划，再补充观察人群与下一步要核实的问题。已有计划字段保留，只补空字段并追加来源；载入来源研究示例也按这个原则处理。

网页不预填示例任务。示例按钮只作探索帮助，不代表已验证需求。网站入口按模板生成检索式，自动执行需使用独立的“自动研究”区域；既有 Reddit 实采区域的旧 API 状态另外标注。页面按“自动研究 → 网站入口 → 保存发现 → 采集计划 → 可展开的参考材料”组织，旧 `#radar` 链接转到统一入口。发现保存在当前站点的浏览器中；从入口手动开始记录时只预填分类和来源名，需要粘贴具体材料链接，网站首页不会自动成为发现链接。

## 不知道搜什么时

| 开始方式 | 先做什么 | 先留下什么 |
| --- | --- | --- |
| 先随便探索 | 按推荐入口浏览，观察人们正在做的任务、求助和试用反馈 | 一个具体任务，或一个想继续了解的链接 |
| 找真实问题 | 读有上下文的求助、使用困难和当前补救办法 | 谁卡在哪一步、已有办法是否有效、仍需核实什么 |
| 找开源项目 | 从项目介绍了解用途，再读使用说明、问题讨论和维护情况 | 解决什么任务、运行条件、试用时要确认的问题 |
| 找 AI 产品 | 看实际功能与演示，再找用户的使用反馈和替代方案 | 谁会用、节省哪一步工作、效果与限制如何验证 |

这四种方式帮助开始探索，不是需求已经成立的结论。对陌生领域先读懂一件具体工作，再决定是否扩大搜索；不要把榜单、Stars 或发布热度当作真实采用与付费的证明。

## 逐站搜索与阅读方法

以下 `{task}` 替换为对应语言的具体任务词。全部模板用于通用搜索引擎，站内搜索方式另行说明。收录不完整、需要登录或只有摘要时，记录实际读取状态。

### Reddit

入口：[从小企业社区开始](https://www.reddit.com/r/smallbusiness/)

**适合找什么：**客户跟进、排班、资料整理、内容制作等重复工作。先找到相关职业的社区，观察人们实际怎么做、哪一步卡住。

**观察信号：**反复手工处理；寻找替代工具；已经尝试过的办法。

**怎么搜索：**先用任务词定位社区，再搜索帖子和评论。站内可用 subreddit: 限定社区；小企业社区只是一个起点，可按人群更换。

```text
site:reddit.com {task} "how do you"
site:reddit.com {task} (manual OR workaround)
site:reddit.com {task} (alternative OR solved)
```

**读结果时：**读正文、回复和楼主后续：谁在什么情境下遇到问题，现有建议是否有效。区分亲身求助与推广；赞数不能说明付费意愿。

**本次访问核查：**本次读取了官方搜索帮助和小企业社区页、帖子片段；未逐条核实评论全文。不同社区的访问条件可能不同。

依据：[官方搜索功能说明](https://support.reddithelp.com/hc/en-us/articles/19696541895316-Available-search-features)；[小企业社区](https://www.reddit.com/r/smallbusiness/)。

### V2EX

入口：[进入问与答](https://www.v2ex.com/go/qna)

**适合找什么：**文件管理、办公协作、设备协同、软件替换和生活服务。适合补充中文用户的使用经历，注意数字工具使用者的人群偏向。

**观察信号：**求推荐；有没有办法；自己拼凑的解决方法。

**怎么搜索：**先看「问与答」，再用任务词搭配「求助、麻烦、替代」搜索主题页。一次只加一个问题词，找到原帖后继续读回复。

```text
site:v2ex.com/t/ {task} 求助
site:v2ex.com/t/ {task} 麻烦
site:v2ex.com/t/ {task} 替代
```

**读结果时：**核对发帖时间、实际使用环境、楼主追问与最终处理方法。近期节点仍有帖子，只能说明入口在更新，不能据此判断整个平台的兴衰。

**本次访问核查：**本次匿名读取了问与答列表及平台介绍；未验证所有节点与回复分页。

依据：[问与答节点](https://www.v2ex.com/go/qna)；[平台介绍](https://www.v2ex.com/about)。

### 知乎

入口：[进入知乎发现](https://www.zhihu.com/explore)

**适合找什么：**了解不同岗位怎样完成一项工作、有哪些限制，以及不同做法的优缺点。优先寻找有具体过程的从业者回答。

**观察信号：**从业者的实际步骤；任务为什么难；评论中的补充条件。

**怎么搜索：**用「任务 + 怎么做 / 麻烦 / 工具」搜索。可先用下方检索式定位问题，再进入原页；能登录时也可使用站内搜索。

```text
site:zhihu.com/question/ {task} 怎么
site:zhihu.com/question/ {task} 麻烦
site:zhihu.com/question/ {task} 工具
```

**读结果时：**看回答者是否亲历、工作规模和事件时间，区分实际经历、观点与产品推荐。搜索摘要只用于定位，读不到正文就记为待核实。

**本次访问核查：**本次发现页可读；问题搜索入口遇到安全验证，未核实普通答案全文和站内搜索结果。

依据：[知乎发现](https://www.zhihu.com/explore)。

### 小红书

入口：[打开小红书探索](https://www.xiaohongshu.com/explore)

**适合找什么：**探索内容创作、小店经营、学习整理和生活实践中的具体步骤。这是候选研究渠道，本轮尚未核实普通笔记样本。

**观察信号：**教程里没讲清的一步；踩坑经历；评论反复追问。

**怎么搜索：**优先在自己的 App 或已登录网页搜索「任务 + 求助 / 踩坑 / 太麻烦」，展开笔记和评论。下方网页搜索用于补充定位，覆盖可能有限。

```text
site:xiaohongshu.com {task} 求助
site:xiaohongshu.com {task} 踩坑
site:xiaohongshu.com {task} 太麻烦
```

**读结果时：**核对亲历过程、操作材料和推广关系。收藏量与「求链接」只能作为线索；进一步看评论里具体没完成的任务。

**本次访问核查：**本次探索页读取超时；可读官方专题页提示登录。普通笔记和评论全文待在浏览器中实际核实。

依据：[官方探索入口（本次未读成功）](https://www.xiaohongshu.com/explore)；[含登录提示的官方专题页](https://www.xiaohongshu.com/worldcup26?wcup_source=market_lianmeng_3)。

### Hacker News

入口：[进入 Ask HN](https://news.ycombinator.com/ask)

**适合找什么：**资料处理、知识管理、团队协作和专业工具选型。Ask HN 看问题，Show HN 看已有产品和试用反馈；注意技术人群偏向。

**观察信号：**具体工作条件；现有工具的缺口；实际试用后的限制。

**怎么搜索：**把任务词和 Ask HN 或 Show HN 一起搜索。前者找讨论问题，后者对照产品；阅读评论中的替代办法和作者回应。

```text
site:news.ycombinator.com/item "Ask HN" {task}
site:news.ycombinator.com/item {task} workaround
site:news.ycombinator.com/item "Show HN" {task}
```

**读结果时：**分别记录作者宣称与使用者反馈。看问题发生条件、替代品为何不够用；分数和发布热度不能说明实际采用。

**本次访问核查：**本次读取了 Ask HN 列表与 Show HN 规则；未对检索结果逐条核实全文。HN Search 的交互查询本次未测试。

依据：[Ask HN](https://news.ycombinator.com/ask)；[Show HN 规则](https://news.ycombinator.com/showhn.html)；[HN Search](https://hn.algolia.com/)。

### GitHub

入口：[进入 GitHub](https://github.com/)

**适合找什么：**开源工具的集成、部署、导入导出、功能缺口和手工补救。适合有具体软件使用场景时查问题，再寻找可用项目。

**观察信号：**复现步骤；维护者回应；临时办法与修复状态。

**怎么搜索：**先定位与任务相关的仓库，读 Issues / Discussions；再读 README 比较已有方案。并非每个仓库都启用这两种讨论入口。

```text
site:github.com inurl:issues {task} workaround
site:github.com inurl:discussions {task}
site:github.com {task} README
```

**读结果时：**查看最新状态、维护者回复与关联修复。关闭的 Issue 可能已解决，也可能不被支持；Stars 和功能请求数量不能直接证明商业需求。

**本次访问核查：**本次读取公开页面和官方搜索文档；只涉及公开仓库，具体问题仍需逐条核实。

依据：[Issues 搜索规则](https://docs.github.com/en/issues/tracking-your-work-with-issues/using-issues/filtering-and-searching-issues-and-pull-requests?tool=webui)；[Discussions 搜索](https://docs.github.com/en/search-github/searching-on-github/searching-discussions)。

### G2

入口：[进入 G2 软件评价](https://www.g2.com/)

**适合找什么：**运营、销售、财务、营销和客服等岗位的软件使用障碍：上手成本、复杂流程、集成限制和权限问题。

**观察信号：**不喜欢什么；解决了什么问题；还要手工完成的部分。

**怎么搜索：**先按任务找到产品类别，再用产品名搜索评论。下方任务词可替换为产品名；同时阅读喜欢、不喜欢和解决的问题。

```text
site:g2.com/products {task} dislike
site:g2.com/products {task} problems
site:g2.com/products {task} alternatives
```

**读结果时：**匹配行业、岗位、公司规模与评价时间。留意 Incentivized / Source 标签，比较正负反馈；激励评价和主动评价者存在样本偏差。

**本次访问核查：**本次首页可读，评价样例经搜索可见正文与标签；直接读取样例超时，未验证登录后筛选与完整评论。

依据：[评价规则与标签](https://legal.g2.com/community-guidelines)；[评价有效性说明](https://sell.g2.com/review-validity)。

### Capterra

入口：[进入 Capterra](https://www.capterra.com/)

**适合找什么：**中小企业和个体经营者的软件选型：功能不匹配、学习负担、维护成本，以及从旧工具迁移的原因。

**观察信号：**Cons 缺点；Switched from 更换来源；Alternatives considered 备选方案。

**怎么搜索：**先找到任务对应的软件，再用产品名查评论。优先看使用时长、缺点、更换前的工具和选型理由，对照相似规模的用户。

```text
site:capterra.com/p/ {task} Cons
site:capterra.com/p/ {task} "Switched from"
site:capterra.com/p/ {task} "Alternatives considered"
```

**读结果时：**记录 Review Source 和激励标签，比较不同来源的评价。区分功能缺陷与场景不匹配；价格感受和更换意愿仍需实际行为佐证。

**本次访问核查：**本次通过搜索读到评价样例及激励标签；直接读取受工具内容类型限制。不能据此判断网站不可用，完整站内搜索未验证。

依据：[评价收集与验证](https://www.capterra.com/resources/how-we-verify-reviews/)；[评价与激励规则](https://www.capterra.com/legal/community-guidelines/)。

### Upwork

入口：[查看公开任务目录](https://www.upwork.com/freelance-jobs/)

**适合找什么：**自动化、资料整理、报表、内容处理、系统连接等外包工作。观察客户需要什么输入、结果和验收条件，以及是否重复发生。

**观察信号：**明确交付物；ongoing 持续工作；发布预算与截止时间。

**怎么搜索：**用具体任务搜索公开岗位，再看完整交付要求。加入 ongoing 或 weekly 找重复工作；记录发布时间和任务是否还开放。

```text
site:upwork.com/freelance-jobs/ {task}
site:upwork.com/freelance-jobs/ {task} "Fixed Price"
site:upwork.com/freelance-jobs/ {task} ongoing
```

**读结果时：**发布预算、商定价格和已付款分别记录。对照不同客户的输入、交付物和频率；一次外包不能直接推断持续订阅意愿。

**本次访问核查：**本次公开岗位通过搜索可见，目录直读返回 403；未验证账户内 Find work 搜索与筛选。

依据：[官方搜索与筛选说明](https://support.upwork.com/hc/en-us/articles/211063078-How-to-search-for-jobs-on-Upwork)；[预算与岗位发布说明](https://support.upwork.com/hc/en-us/articles/211063408-How-to-post-a-job)。

### Product Hunt

入口：[进入 Product Hunt](https://www.producthunt.com/)

**适合找什么：**已有一个任务或问题时，查看谁在解决、怎样定位、如何使用，以及用户提到的限制。主要用于方案发现。

**观察信号：**目标用户与使用方式；具体试用反馈；与替代品的比较。

**怎么搜索：**在首页搜索任务词或按类别浏览；从发布页进入官网核对功能、演示和价格。下方检索式也能定位产品和论坛讨论。

```text
site:producthunt.com {task}
site:producthunt.com {task} alternatives
site:producthunt.com/p/ {task}
```

**读结果时：**区分作者介绍、祝贺评论和实际试用。发布热度、投票和榜单不能说明持续使用或付费；回到原始用户问题核实。

**本次访问核查：**本次首页和官方帮助可读，搜索与类别浏览有官方说明；未登录、投票或评论，具体产品尚未试用。

依据：[浏览与搜索说明](https://help.producthunt.com/en/articles/2305333-getting-started)；[产品论坛说明](https://help.producthunt.com/en/articles/11432379-maker-s-guide-to-product-forums)。
