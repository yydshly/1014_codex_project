        原文证据

        原话片段 + 原始链接 + 上下文。没有明确数字时，频率与耗时填“未知”。

        整理判断

        问题归类 + 同类独立来源 + 现有解决办法 + 待核实的问题。每项推断注明依据。

        真正的批量抓取，怎样逐步落地？
        先探索

        公开搜索 + 人工小样本

        先确认关键词能找到真实求助，读正文与后续，保存字段和采集范围。搜索摘要只当定位入口。

        再整理

        导入原文 + AI 提取

        将可读取的内容或导出文件交给 AI，按同一字段提取、附证据、去重归类；人工抽查原文与被排除的记录。

        需要持续采集时

        逐站接入 + 增量更新

        确认数据访问范围后，按来源 ID 去重，记录采集时间、更新状态与失败重试，持续补充新内容和已解决的反例。

        接口范围参考（2026.10.15 核查）：Reddit Data API 需获批访问；Apple 与 Google Play 的开发者评论接口面向自己有权限的应用；Upwork API 需申请，当前仅支持个人或内部用途。采集方案要按具体平台确认。

        01

        从案例倒查：最初的问题在哪里？

        阅读产品与推广案例时，追问目标用户是谁、最初出现过什么求助、当时的替代方案有什么缺口。

        留下的产出：观察人群、任务词与原始线索。
        02

        把渠道与工具线索，变成采集入口

        从社区、应用评论、外包任务和行业讨论进入具体场景。读用户原话与后续回复，回看问题是否已经解决。

        留下的产出：可回溯的来源记录，而后才是我们的解释。
        03

        借助 AI 找相似问题，保留人的判断

        AI 可以扩展关键词、翻译、提取和聚类。我们要核实原文、区分独立来源，并判断是否还有值得追问的缺口。
