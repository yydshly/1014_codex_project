# 004 · 问题驱动研究工作台

从 JasonZhu.AI 个人网站研究出发，重点探索需求发现与采集。前端使用原生 HTML、CSS、JavaScript；本地 Node 服务通过已登录的官方 Codex CLI 执行公开搜索、原文读取和分析，并保留旧的 Reddit API 实验接口。依赖由 `package-lock.json` 固定。

## 阶段整理与公开页面

`research.html` 为产品总览，完整说明能力、原理、价值、目标、适用场景、十类产品扩展和证据边界；引导图沿用 `assets/product-overview.png` 原图。`index.html` 保留研究工作区，现有记录和存储键保持兼容。

`node build.mjs` 是整个仓库的 Pages 构建入口，按锁文件补齐依赖，执行语法检查与测试，再以 `--static` 构建。公开工作区标注静态模式，不请求不存在的研究 API；自动研究输入禁用并提供本地运行说明，历史样本直接读取已保存数据。来源、计划、发现、JSON 导入导出仍在浏览器内运行。公网与本地站点存储隔离，需用 JSON 备份迁移。

`npm run build` 保持本地执行模式。两种模式均包含产品总览、原始全景图、工作区和完整文档；服务器代码、环境变量与 `.runtime` 不进入静态发布产物。发布清单为根目录 `web/pages.json`，状态见 [部署记录](../deployment.json)。

## 本地运行

需要 Node.js 22 或更新版本。首次运行先安装依赖：

```powershell
npm ci
```

然后在本目录运行：

```powershell
.\start.ps1
```

打开 [004 本地预览](http://127.0.0.1:4176/1014_codex_project/004-jasonzhu-ai/)。可用 `./start.ps1 -Port 4180` 指定其他端口。

也可以逐步运行：

```powershell
npm run check
npm run build
npm run preview
```

修改前端文件后重新构建并刷新网页；修改服务端或配置后重启服务。本地预览仅监听 `127.0.0.1`，关闭运行窗口或按 Ctrl+C 结束服务。

## 输入方向并自动研究（2026-10-17）

在 `#research` 输入 2–300 字研究方向，选择综合探索、真实需求、GitHub 项目或 AI 产品，再点击“开始研究”。默认勾选完成后保存到发现库；取消勾选时只保留运行报告，之后可点“保存本轮发现”。运行过程会显示已收到的搜索和打开次数，可停止、刷新连接、查看过去的研究。

使用条件是本机安装官方 Codex CLI 且已完成 `codex login`。服务启动时检查 `--version` 与 `login status`，不读取或复制登录令牌。Windows 默认使用 PATH 中的 `codex.exe`，其他系统为 `codex`。必要时在 `.env.local` 配置 `CODEX_BIN` 为官方可执行文件的完整路径，`CODEX_MODEL` 可指定账户支持的模型，留空使用 CLI 默认模型。`RESEARCH_TIMEOUT_MS` 默认 240000，允许 60000–600000。

点击开始才消费本机 Codex 账户额度；不自动重试。仅把本次方向、研究目的和固定研究说明交给模型，现有发现与采集计划不会上传。可从计划带入角色和任务到输入框，再自行编辑。公开网页被视为资料，不允许其中的指令改变研究范围。

执行链路：同源 POST `/api/research/runs` → 单个后台 CLI 任务 → 实时记录公开搜索动作 → 结构化候选 → 关联来源打开记录并尝试独立读取短引文 → 页面轮询结果 → 当前浏览器发现库。一次最多保留 3 条发现，提示模型最多 3 组查询、6 个来源；执行器额外限制 16 次公开动作和运行超时。没有符合条件的来源会返回零条并说明理由。

来源分三级：“本地逐字匹配短引文”“有原文打开记录，AI 摘录待独立复核”“只有摘要或不可读”。只把前两类主来源保存为发现；第三类辅助材料仍标明限制。产品推广不能直接作为真实用户需求。模型分析、来源中的自述以及付费意愿都仍需后续核实，工具记录不证明全文读取或内容真实。

自动入库按记录 ID 和规范化链接去重，包括回收站；它不会覆盖已有理解、下一步或状态，也不会自动恢复已移入回收站的记录。规范化忽略 `www`、末尾斜杠、片段和常见跟踪参数；需要为同一页面保留另一观察时，仍可手动创建。手动 JSON 导入继续按 ID 和修改时间合并，两种操作规则不同。

浏览器刷新会重新连接运行中的任务；若本轮勾选自动保存且浏览器成功存下运行标记，结束后会继续入库。关闭浏览器时服务可以继续，重新打开后恢复；服务重启则将未完成运行标记中断，不自行再次调用模型。运行 JSON 在忽略提交的 `.runtime/auto-research/`，历史选择器显示最近 20 轮；发现仍在浏览器 `research-004-findings-v1`，不是服务器同步库。浏览器存储失败会保留服务器报告并提示手动重试。

参考：[官方非交互模式](https://learn.chatgpt.com/docs/non-interactive-mode)、[CLI 搜索参数](https://learn.chatgpt.com/docs/developer-commands?surface=cli)。`--search` 启用联网，`--json` 读取公开动作，`--output-schema` 限定格式；采用临时只读任务、忽略自定义配置，禁用 shell、MCP 应用、插件、子代理和浏览器控制。只保存公开动作与最终结构化结果，不保存模型推理、原始诊断或登录凭据。

`server/auto-verify.mjs` 改编自本仓库 `009-demand-discovery/web/server/verify.mjs`，2026-10-17 工作副本（未发布版本）；执行方式参考同项目的 CLI 集成。两者是本仓库原创代码，并非复用 JasonZhu.AI 源码；未另授第三方许可证。004 将其复制为独立模块，新增来源关联、截止时间、取消信号、Windows 原子读写协调与发现库转换，不依赖 009 的目录或服务。

## 统一研究入口（2026-10-16 更新）

`#directory` 是统一的网站入口工作区，位于自动研究之后，包含 Reddit、V2EX、知乎、小红书、Hacker News、GitHub、G2、Capterra、Upwork 和 Product Hunt。旧搜索区已合并到这里，旧 `#radar` 链接转到此入口。页面随后展示“保存发现”和采集计划，再提供默认收起的方法、样本与研究背景。

不知道搜什么时，可先选“先随便探索 / 找真实问题 / 找开源项目 / 找 AI 产品”，按推荐网站与三步引导直接浏览，找到具体任务后再填写关键词。四种开始方式用于组织探索顺序；现有的社区求助、产品反馈、付费任务、现有方案分类，以及语言和网站/用途筛选仍可帮助缩小范围。

观察人群可选填。填写中英文任务词后更新检索式，选择 Bing 或 Google，打开搜索或复制。中文入口使用中文词，英文入口使用英文词；对应语言留空时不生成含空任务的查询，仍可访问网站入口。切换开始方式保留已填任务词；示例任务只在点击时填入，不代表已验证需求。每个入口包含用途、搜索方法、三条检索模板、阅读要点、访问限制与官方依据。

“加入采集计划”将入口及已有搜索信息追加到来源字段，只补充计划中的空字段。载入来源研究示例同样保留已填内容并追加来源。重复添加不重复写入，来源达到长度上限时要求先整理。数据在 `data/research-entries.json`，说明快照在 `../RESEARCH_ENTRIES.md`。此导航为本地模板与外部链接，无需 API；原有 Reddit 能力单独说明如下。

## 保存发现（2026-10-17 更新）

`#discoveries` 位于研究入口与采集计划之间，保存已经找到的具体材料。先选“需求线索 / GitHub 项目 / AI 产品”，填写标题和具体链接；来源、原文摘录、自己的理解与下一步可选填。原文摘录与自己的理解分别保存，便于后续回到来源核实。

从网站入口开始记录时，只预填分类和来源名称。需要手动粘贴读到的帖子、仓库或产品页面链接，网站首页不会自动当成发现链接。记录不依赖任务词，也不要求先建立采集计划。

每条记录可以编辑，并使用“待研究 / 研究中 / 已整理 / 暂缓”标记进展。列表按更新时间从新到旧排列，支持关键词、类型和状态组合筛选。删除后记录进入回收站，可恢复。卡片中的带入计划操作会追加来源，并只补充计划中的空字段；已有研究内容保留。

导出与恢复方式：

- **JSON**：导出全部记录，包含回收站，用于备份或在另一浏览器恢复。导入先显示预览，确认后按记录 ID 合并，保留 `updatedAt` 较新的版本；不按相同 URL 去重，允许为同一材料保留不同研究记录。
- **Markdown**：导出所有未删除记录，包含链接、摘录、理解、下一步与状态，方便交给 AI 继续研究或保存到笔记。筛选用于浏览，不会把导出范围缩小到当前筛选结果。

发现保存在当前站点的 `localStorage`，键为 `research-004-findings-v1`，与采集计划独立。手动保存不抓取链接内容；自动研究由服务执行，再将结果保存到同一发现库。记录不跨浏览器同步；清除站点数据会移除本地保存内容，可用导出的 JSON 恢复。

当前单库上限为 1000 条（含回收站），导入文件上限为 10 MB。页面只提供移入回收站和恢复，暂未提供永久删除或分库管理。

## OpenAI 本地接入

按照 `.env.example` 在忽略提交的 `.env.local` 中配置 `OPENAI_API_KEY`，或使用 `OPENAI_ENV_FILE` 指向已有本地配置文件。不要把密钥写入页面、研究数据或聊天消息。`OPENAI_MODEL` 默认采用官方搜索文档示例 `gpt-6-astra`，实际账户的模型与工具访问仍需验证。

重启服务后刷新网页接入状态；点击“用 OpenAI 搜索并分析”才发起请求。支持任务词、优先社区和最多 2–6 条记录。另一个按钮只重新分析保存的两条材料，不执行新的采集。请求会使用 API 账户额度；当前未配置时不会发送请求。

服务通过 AI SDK 7.0.140 与 OpenAI provider 4.0.93 调用 Responses API，启用 `web_search`、限定 `reddit.com`，并保留实际返回的来源。帖子正文视为不可信数据，不能改变分析指令。

新运行保存在忽略提交的 `.runtime/`，包括状态、用量和最新成功结果。失败或中断保留上次成功结果。页面分开标记“引文与保存片段核对”和“API 引用、原话待独立复核”；API 的来源引用本身不等于取得了完整原文。

## 能力与数据边界

“网站入口”和“采集计划”按固定模板生成检索式与指令，不触发 AI 调用；“自动研究”在点击开始后调用本机 Codex 联网；“保存发现”统一管理手动记录和自动研究候选。点击网站链接或“打开搜索”在新标签访问外部页面，后者向搜索引擎传入检索词。计划与发现分别保存在浏览器 localStorage；“Reddit 实采”区域使用单独的旧 API。更换浏览器或端口不会共享计划或发现，可通过 JSON 导出后在新环境合并导入。

来源使用 [demand-sources.json](../demand-sources.json) 的 2026-10-14 研究快照；20 条记录来自 18 个不同链接，定向采样偏向文件与电商工作流，不代表整个市场。历史抱怨、任务发布预算和实际购买意愿分别判断。
