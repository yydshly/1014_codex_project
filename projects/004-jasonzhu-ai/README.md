# 004 · 问题驱动研究工作台

从一个问题出发，搜索公开资料、尝试读取原文、分析与筛选需求线索、GitHub 项目和 AI 产品，保存来源、理解和下一步。底层由本地服务调用 Codex，模型帮助理解，程序检查来源条件，人继续试用与验证。价值在扩大观察范围和积累可继续的研究记录；目标是服务个人开发者的研究决策，可扩展为研究助手、工具评估台、需求雷达与团队研究库。当前阶段整理已完成，产品需求与商业效果待验证。

![004 产品全景图：能力、原理、价值、适用方向与可扩展产品](assets/product-overview.png)

## 产品定位与阶段目标

- **能力：**10 个来源入口、实际联网研究、三类发现保存、采集计划与备份。
- **原理：**问题 → 公开来源 → 搜索和读取 → 模型分析与来源检查 → 发现库 → 人工验证。
- **价值：**帮助个人开发者扩大观察范围、比较现有方案、保留研究依据，减少重复寻找与重新理解。
- **目标：**从“想研究什么”推进到“依据是什么、下一步做什么”，逐步积累可复用的研究资料。
- **扩展：**个人研究助手、GitHub 评估、AI 选型、需求雷达、行业情报、团队研究、反馈整理、证据关联 PRD、简报服务与研究接口。

产品总览为 `web/research.html`，工作区保留在 `web/index.html`。公开静态版本提供阅读、导航、计划与浏览器发现库；自动研究需本地 Node 服务和 Codex 登录。完整边界与扩展缺口见 [产品说明](PRODUCT_OVERVIEW.md)。

## 查看网页

需要 Node.js 22 或更新版本。在 `projects/004-jasonzhu-ai/web/` 首次执行 `npm ci`，再运行 `./start.ps1`，打开 [004 本地演示](http://127.0.0.1:4176/1014_codex_project/004-jasonzhu-ai/)。

页面按“自动研究 → 网站入口 → 保存发现 → 采集计划 → 可展开的参考材料”组织。自动研究复用本机官方 Codex CLI 的登录状态和额度，不需要另填 API 密钥。旧的 Reddit Responses API 实验路径仍未配置独立 API 凭据，保留历史样本；它与新的自动研究入口分别运行。完整说明见 [Web 文档](web/README.md)。

## 2026-10-17 自动研究接入与实测

从网页提交“自由职业设计师如何整理客户零散的修改意见”，真实执行约 71 秒。收到 2 次搜索动作、3 次打开动作（对应 2 个不同页面）；模型返回 5 个来源和 3 个候选，来源门槛最终保留 1 条并自动入库，其余 2 条缺少可关联的原文打开记录。另列出 2 条推广材料的排除理由。

保留的发现是“让客户继续使用原渠道，由设计师维护一份可追溯修改清单”。原有 1 条手工记录保留，发现库共 2 条；重复点击保存显示新增 0 条、跳过 1 条。重启服务及刷新后，报告与发现都可恢复。记录属于待研究线索，不代表已验证产品需求。

本地独立抓取未成功取得这 5 个页面，因此没有任何引文标记为“本地逐字核验”。工具打开记录和模型摘录分开标注；模型自述的页数与实际动作记录不一致时，以程序记录为准。[真实运行快照](research-runs/2026-10-17-auto-client-feedback.run.json)保留这次输出及限制，未将它作为默认样本注入网页。

语法检查、构建及 39 项测试通过，新增覆盖自动执行接口、来源条件、两类产品记录、跨站拒绝、重复提交、取消、失败、重启恢复和自动入库去重。运行历史保存在本地服务目录，发现保存在当前浏览器；更换浏览器仍需导出备份。

## 2026-10-17 保存发现

同日另用“个人开发者发布产品后的反馈整理”实跑：第一轮自动保留 Fider，ClearFlask 与 Canny 因主来源缺少可关联的打开记录而未入库；收窄范围、逐个打开主来源后，第二轮保留 ClearFlask 与 Canny Autopilot。两轮合计3次搜索、5次打开，新增2条 GitHub 项目和1条 AI 产品，发现库共5条，原有2条逐字段未变。当前会话另回查官方资料，并通过编辑界面补充研究价值、适用阶段和部署限制。未部署项目、未试用产品；官方功能说明不等于独立用户效果。两轮输出及[最终发现库备份](research-runs/2026-10-17-developer-feedback.findings.json)保存在 `research-runs/2026-10-17-developer-feedback*`，刷新与实际导出已验证。

- 每条发现必填标题和具体链接，可选填来源、原文摘录、自己的理解与下一步。分为需求线索、GitHub 项目、AI 产品三类，用“待研究 / 研究中 / 已整理 / 暂缓”记录进展。
- 保存后可编辑，按关键词、类型和状态筛选，最近更新的记录排在前面。删除进入回收站，可恢复；带入采集计划时追加来源并只补空字段。
- JSON 导出包含全部记录和回收站，重新导入时先预览，再按记录 ID 合并并保留更新时间较新的版本；相同链接可保留不同研究记录。Markdown 导出当前未删除的记录，方便交给 AI 继续研究。
- 记录独立保存在当前站点的浏览器中，不跨浏览器同步；自动研究只发送本次填写的方向和研究目的，已有发现与采集计划不会自动上传。需要备份或换浏览器时，可先导出 JSON。

本次已通过语法检查、构建与 25 项测试。隔离端口的浏览器验证覆盖三类记录的保存与编辑、刷新恢复、筛选与排序、回收站恢复、JSON 实际下载与合并导入、Markdown 实际下载，以及带入计划时保留已有内容；桌面与同源窄屏预览无横向溢出。详细验证范围见 [Web 说明](web/README.md)。入口的公开访问记录仍以 2026-10-15 的核查为准。

## 为什么研究这个项目

JasonZhu.AI 将个人内容、工具介绍、邮件订阅与服务展示放在同一网站。对正在做项目复现和网页演示的独立开发者，它提供需求定位、案例表达、传播与联系入口的参考。

本轮重点是个人网站内容对你的实际价值。最值得借鉴的是把研究成果接到目标用户与真实反馈上的方法；具体产品方向和商业效果需要通过自己的试验判断。

建议优先学习需求与受众定位、真实案例的写法和小范围推广实验，再按反馈决定是否增加网站功能或发展产品服务。详细分析见 [研究记录](RESEARCH.md)。
