# 008 · Specreel 实测：对当前研究库有什么帮助

研究日期：2026-10-15。固定版本、许可与输出入口见 [README](README.md)。

## 结论

Specreel 0.2.0 可以把定义好的浏览器操作变成可暂停、逐步浏览、定位到具体画面的演示，也能导出 MP4。最直接的用途是为研究库里的每个工具保存一条关键操作路径，让读者看到它实际怎样工作；以后重复执行录制脚本，可以更新材料。

第一次使用的主要工作仍是选流程、写操作、确定检查与检查回放。当前网址推荐只能发现基础表单，生成脚本还存在语法错误。只展示一次时准备成本较大；持续更新、需要反复解释的工具页面更容易获得复用价值。这是本轮体验判断，尚未进行外部用户理解度或节省时间的对照研究。

## 实际生成的内容

| 02 采集计划 | 改任务词、切 App 评论/Reddit、带入计划、填写替代办法与核实问题、生成并切换指令 | 21 | 8 | 约 26 秒 |

004 没有独立 OpenAI API 凭据。本轮只读取已有两条会话样本与历史来源，操作搜索词和计划生成器，没有执行新一轮自动搜索或模型分析。

## 网址推荐结果

原生 recommend 读取服务器 HTML，发现一个页面和四个基础流程：三个表单、一个搜索框。三个表单使用重复的通用标题，填入 Sample text，提交动作与结果检查留为 TODO。它没有识别本页的“原话 → 已有办法 → 来源条件”核心路径。

生成文件是 JavaScript，但第 19 行等使用 # TODO 注释，node --check 返回 SyntaxError: Invalid or unexpected token。2026-10-15 的本地历史诊断记录了推荐脚本的语法错误，没有执行或宣称该脚本成功；本次研究页面展示诊断结论，不把该脚本当作可运行成果。最终演示使用独立编写的实际操作脚本。

## 实测限制

1. 默认字幕只描述操作和断言，如 Click、Confirm；没有说明为什么这样观察、怎样判断需求，还会把辅助截图显示为 screenshot。
2. 当前 Windows 环境默认视频字体是 Arial，中文片头与字幕出现方框；HTML 的浏览器字体能显示中文。适配使用微软雅黑后 MP4 中文恢复，见 [原生片头](assets/native-title.png)与[适配片头](assets/chinese-title.png)。
3. 默认节奏偏快，复杂原文和长指令需要暂停、逐步查看或放大。播放器有手动放大，但没有按业务目标自动放大的镜头。
4. 播放的是保存画面；读者可以控制回放，业务输入和标签切换需要打开 004 原页面。
5. 绿色结果只表示所选浏览器断言通过，不能证明全部功能、来源内容、真实需求或商业价值有效。

### 本质：浏览器执行与演示生成分别由谁负责

Specreel 的核心是浏览器记录的演示生成引擎：读取 Playwright `trace.zip`，把结构化动作、检查和画面编排为可以观看、分享和重新生成的材料。它可以由 Agent 组织使用，也可以完全不接 Agent 或模型。

准确主链为：**目标与流程 → 人或 Agent 准备脚本 → Playwright 启动独立浏览器、执行和采集 → trace.zip → Specreel → HTML 回放 / MP4 / GIF。**

| 层次 | 实际职责 | 证据与边界 |
| --- | --- | --- |
| 目标与条件 | 选业务路径、准备输入、账号权限与完成标准 | 需明确任务，不等于工具会自行发现全部业务价值 |
| Agent / 模型（可选） | 组织工具、协助写脚本、规划步骤或改写说明 | 已有 MCP、技能、`nlflow` 等源码，完整 Agent 闭环未测 |
| Playwright / 浏览器 | 启动浏览器，点击、填写、检查，保存动作与画面 | 三条实测由 `capture.mjs` 无头执行 Chromium；并非聊天软件内置浏览器 |
| Specreel 核心 | 解析动作、匹配帧、生成规则字幕、步骤和输出 | 可离线处理已有 trace，不必再启动浏览器或调用模型 |
| 播放与导出 | HTML / JavaScript 回放；Pillow 合成画面，FFmpeg 编码视频 | 回放保存的画面，不重新操作真实网站 |

`trace.zip` 内有事件日志、动作前后时间、参数、断言或错误、页面快照与 `screencast-frame` 图片。引擎读取 before / after 事件，过滤辅助动作、合并步骤、按时间匹配画面，再生成字幕和点击标记。单流程播放器可保留抽样运动帧，便携合集每步保留一张图；它不是对任意桌面应用的连续全屏录制工具。

网页播放、暂停和下一步只控制保存素材。MP4 使用图像和编排时间编码，附标题、字幕与结果卡；选用预生成配音时可以加入音轨，本项目既有中文视频均无声。要再次完成真实任务，需要重跑脚本或操作原网站。

### Agent 和模型：已有可选源码，完整链路尚未实测

固定版本确有 Agent 使用路径，不能只描述成没有 Agent 接入的脚本工具：

- `specreel_mcp.py` 提供 `recommend`、`render`、`render_one`、`publish`、`summary`、`init_config` 六个工具，包装同一 CLI；Agent 技能说明发现流程、补 TODO、执行脚本、渲染与分享。MCP 自身没有浏览器执行工具，也没有直接的 MP4 参数，完整链路需外部 Agent 串联 Shell、Playwright 与渲染导出命令。
- `recommend` 默认读取服务器 HTML，`--browser` 可启动 Playwright 读取渲染页面；可提供登录信息。`--ai` 对已发现的候选流程重排或改名，不能保证理解全部业务。
- `nlflow` 使用自然语言和已发现的页面上下文生成 Playwright 代码；可选 `--verify` 无头试跑、根据页面与错误进行有限修复，并调用模型检查终态是否符合目标。这是固定代码中的可选能力，不是本项目已经证明可靠的任意网站自主操作。
- `--ai` 旁白改写、`--voice` TTS 及其他模型辅助能力需要相应外部服务和密钥。核心规则字幕与本次录制、生成不需要模型。

因此可以说“Agent 调用模型和工具组织浏览器自动操作，再交给 Specreel 生成视频”，但模型不会自行加载浏览器，Specreel 也不强制依赖聊天应用内置浏览器。已有 trace 可以直接渲染；Agent 组合路径与本次脚本实测应分别标记。

### “不需要人参与”具体成立在哪个阶段

| 阶段 | 可以自动做什么 | 需明确或可能人工处理的事项 |
| --- | --- | --- |
| 准备 | Agent 可协助发现候选路径、编写和修改脚本 | 目标、环境、账号授权、数据、成功标准；生成脚本仍可能不完整或出错 |
| 执行与生成 | 条件就绪后自动操作、检查、采集、编排字幕、导出回放与视频；无需人逐步点击或剪辑 | 目标站点与依赖可用；登录、验证码、页面变化和异常可能中断执行 |
| 结果与分享 | 可生成检查摘要，选用发布或持续构建流程 | 检查范围、教程清晰度、敏感内容、是否真正完成任务及是否适合分享 |

上游 CI 示例说明重复执行和材料更新可以接入构建链路；本项目没有运行该上游 CI 或验证自主发布。我们能确认已有流程的自动执行与生成，不能据此保证任意任务从提出到验收永远无需人参与。

自动检查有范围：所选断言通过不等于完整产品或业务事实被验证；`nlflow` 目标检查依赖模型对有限终态信息的判断，不能视作独立验真。更新徽标来自操作字幕签名，样式、数据或业务变化未必都被标出。

### 实测成果与未验证项

2026-10-15 生成三个流程，每条均有原生和中文适配：真实样本 11 步 / 6 检查，采集计划 21 步 / 8 检查，来源筛选 15 步 / 7 检查；HTML 时长约 14 / 26 / 18 秒。第二条中文 MP4 为 31.77 秒、1280 × 948、H.264、617,384 字节、无音轨。视频含片头片尾，故与 HTML 时长不同。

已验证中文字体修正、回放控制、MP4 规格及分段读取，以及任务词变化后重跑生成新回放和更新标记。原生推荐没有找到核心路径且生成 JS 有语法问题，最终录制脚本为独立编写；此项限制保留，不能改写成只给网址便自动成功。

未验证：完整 MCP / Agent 闭环、`nlflow` 本地执行与修复、AI 字幕改写、TTS、浏览器朗读、Cloud、上游 CI 自动发布、长期无人值守成功率，以及整体节约工时、学习效果或付费需求。2026-10-19 沿用既有记录与素材，不产生新的业务实测结论。

### 与普通录屏的差异、场景和我们的取舍

指导、备忘和产品展示不是本工具独有的用途，普通录屏同样能做。Specreel 的潜在增量在于复用动作与检查的结构化记录、按步骤查看，以及用已有脚本重新运行、生成更新材料。

首次需要选流程、准备脚本与数据、检查输出；页面改动仍可能维护脚本。重复更新或已有自动化测试时，这些成本才更可能被摊薄。连续动画、三维房间、桌面操作或一次性解释，普通录屏通常更直接。本项目没有对照证明它整体比录屏更省时间。

| 使用场景 | 对我们的意义 | 仍需补充 |
| --- | --- | --- |
| 指导演示、培训 | 给别人可暂停、逐步看的路径与预期结果 | 选核心任务、补业务说明、检查是否看懂 |
| 个人操作备忘 | 给未来自己保存当时如何操作成功 | 背景、原因、经验与版本，不能靠画面替代思考记录 |
| 项目研究、产品介绍 | 从能力描述走到真实输入、动作与输出 | 来源、限制、分享范围与清晰节奏 |
| 持续开发、教程更新 | 同一流程复用为检查与演示，重跑更新 | 维护脚本、账号、数据，处理失败与页面变化 |
| 团队交接、客户验收 | 为过程、选定结果与限制留下可复查材料 | 权限、责任、验收标准与背景说明 |
| Agent 网页任务记录 | 探索为自动工具执行提供可观看证据 | 串联授权、记录、恢复、隐私与验收；完整产品和闭环未验证 |

候选扩展产品包括操作档案、随版本更新的帮助中心、Agent 任务回放系统、客户验收演示包。它们还需任务和版本管理、访问控制、说明、审阅、通知等能力，以及需求与付费意愿验证；不是本库已经交付的完整产品。

当前保留为可复用工具，稳定且反复使用的网页流程按需采用，不要求所有研究项目接入。下一次有真实更新需求，再比较同一任务首次准备、后续维护的总耗时和读者理解度；没有重复需求时，保留成果即可。
