008 / BROWSER FLOWS, MADE WATCHABLE

让网页操作，
变成演示与备忘。

Specreel 把浏览器操作记录加工成分步网页回放和视频。可以由 Agent 调用模型规划流程，再交给浏览器工具执行；准备好的流程，在运行阶段无需人逐步点击。

01 / THE SHARED UNDERSTANDING

先把能力、效果和意义放在一起。

008 是这个研究集中的 Specreel 项目。此前讨论主要围绕其他库，本页将保存的实测记录与本次形成的理解统一整理。

能力是什么

把已有操作过程转成可以观看的材料。

读取 Playwright 浏览器记录，自动生成步骤、画面、点击标记与检查信息；输出单条回放、演示合集、MP4 / GIF，并可接入发布流程。自动化接入层还有 MCP、Agent 技能与可选模型能力。

底层原理是什么

操作日志与画面帧共同决定演示。

Playwright 执行网页动作并采集事件、截图帧和快照。Specreel 解读 trace.zip，按时间把动作和画面对应起来；网页通过 JavaScript 播放，视频由图片、字幕与时间编排后交给 FFmpeg 编码。

已经得到什么效果

三条真实操作回放与三段视频。

我们用 004 的保存样本、采集计划与来源筛选做实测，保留原生和中文适配。第二条中文视频为 31.77 秒、1280 × 948、无音轨。本次页面直接播放这些既有成果，不重新调用模型制作。

适合哪些使用场景

指导别人，也给未来的自己留操作备忘。

可以服务产品介绍、使用教程、客户培训、团队交接和需要更新的操作档案。它保存“怎样做、看到了什么”；选择原因、业务背景与经验判断需要额外记录。

自动化到什么程度

明确流程之后，可以自动执行和生成。

准备好脚本、运行环境、账号权限、数据与检查条件后，录制、解析、编排、导出可以连续运行，无需人工逐步点击或剪接。首次定义、登录授权、异常处理与最终验收仍可能需要人。

对你的实际意义

保留一条可重跑、可解释的操作路径。

对稳定、反复使用的网页流程，它有潜在复用价值。一次性展示或持续的三维视觉效果，普通录屏通常更直接。我们保留它作为按需工具，未证明整体省时，也不要求每个研究项目都采用。

03 / HOW IT WORKS

浏览器负责执行，Specreel 负责加工记录。

下面可以切换两种组织方式，并点击每一层查看职责。Agent 和模型是可选入口；真正执行浏览器操作的是工具。

原理交互示意；点击节点不启动浏览器、不调用模型，也不生成新的录像。

记录的输入

有画面，也有结构化动作。

trace 中包含动作、参数、时间、检查结果、画面帧与页面快照。它知道“点击保存”，来自记录中的 click 动作和目标信息，而不是默认让模型看视频猜测。

网页回放

图片帧 + 步骤数据 + 播放逻辑。

画面可嵌入 HTML，JavaScript 按编排后的步骤和时间切换，展示点击位置、字幕和失败信息。点击“下一步”只是查看保存记录；重新执行业务要重新跑操作脚本。

视频导出

生成画面，再编码成视频。

Pillow 处理标题、字幕与画面合成，FFmpeg 编码 MP4；有可选配音时可合入音轨。我们验证的三个中文视频均无声，没有测试 AI 字幕、TTS 或浏览器朗读。

04 / WHAT CAN RUN UNATTENDED

无需逐步点击，可以做到。
从头到尾无需判断，不能一概保证。

“不需要人参与”需要说清楚指哪个阶段。对于准备就绪的确定流程，执行和生成阶段可以无人值守；全过程仍存在目标、权限和验收的决策。

准备阶段 / 人或 Agent 协作

明确要做什么。

选择有意义的流程、准备运行环境和账号权限、数据与检查条件。Agent 可协助规划与写脚本，最终任务目标及授权仍需明确。

自动执行区 / 条件满足后无需人逐步操作

自动操作、采集、生成。

Playwright 按脚本执行并检查，保存 trace；Specreel 解析、匹配画面、生成字幕、回放和视频。接入现有构建流程后，可在后续重新运行。

例外与验收 / 仍可能需人

判断成品是否合适。

首次登录授权、验证码、页面改动和异常流程可能打断执行。自动检查覆盖已定义条件；教程是否清楚、敏感内容是否适合分享、任务是否达到目的仍需确认。

Agent 能把准备工作也自动化到哪里？

固定版本存在 MCP / Agent 技能入口，以及可选自然语言流程生成、试跑、失败修复与目标检查。可以让 Agent 组织多种工具协作，降低人工编写流程的负担。这些能力有源码依据，我们尚未验证任意任务的完整 Agent 闭环或成功率；MCP 工具、Shell、Playwright 和模型各自承担不同职责。

05 / COMPARED WITH SCREEN RECORDING

观看效果相近，准备和更新方式不同。

指导演示和备忘，普通录屏同样能做。Specreel 的潜在增量是复用结构化操作与检查，持续重新生成演示。

比较角度普通录屏Specreel 这套工作流
主要输入屏幕的连续画面，按需录声音浏览器动作、画面帧、时间和检查记录
第一次制作开始录制并手动操作，准备通常直接准备或复用脚本与数据；可以让 Agent 协助
教程的形式视频，可另行剪辑、加字幕和章节按步骤生成网页回放，另可导出视频、GIF 和合集
产品更新后重新操作与录制，需要时剪辑重跑流程再生成；控件与流程改动可能要维护脚本
结果检查通常靠观看和另外的验证可以复用预先定义的自动检查，覆盖范围取决于脚本
适合的内容一次性说明、桌面操作、连续动画与视觉作品结构稳定、需要重复展示和更新的网页业务流程
目前没有“整体比普通录屏更省时间”的实测结论。我们的首次准备包含选流程、编写脚本、检查输出与中文字体适配；自动推荐、默认字幕与播放节奏都存在限制。

06 / USE CASES & PERSONAL VALUE

给别人一份指导，给自己一份操作备忘。

真正要判断的是：这条流程是否会重复使用、是否常变、是否值得维护成可重跑的记录。

对这个研究集

把“研究过”变成“能看到怎么用”。

为 004 这类工具挑一条关键路径，关联说明、来源、结果和回放。资料能留存与复查；目前尚未测试外部读者是否更容易理解。

对未来的自己

少重新摸索某个稳定操作。

保存当时怎样完成、看到了什么结果、用了哪一版流程。旁边补上任务背景、为何这样选择和注意事项，才能形成完整的经验记录。

对后续 Agent 工作流

让工具执行留下可展示的证据。

可以探索把 Agent 的网页任务接到采集与演示生成链路，让结果更容易回顾。完整授权、错误恢复、隐私处理、验收和长期维护仍需另行实现及验证。

我们的当前取舍：保留备用，按需使用。

稳定、反复使用且经常要更新的网页流程，值得评估接入；临时解释一次、展示小幽灵和 3D 房间等连续视觉效果时，普通录屏通常更直接。不因为它能做教程和备忘，就要求每个项目都采用。

下一次有真实重复需求时，用同一任务比较首次准备、更新维护的总耗时，以及别人是否看懂。当前未证明整体省时、学习效果、商业需求或付费意愿。

还可以扩展成什么产品？

候选方向包括：按项目整理的操作档案、随版本更新的帮助中心、Agent 网页任务的可回放记录、客户验收演示包。它们还需要任务管理、版本关联、访问控制、背景说明和质量检查等产品能力；这些是探索方向，不是本库已经交付或需求已验证的产品。

07 / THE QUESTIONS WE ASKED

把讨论中容易混淆的地方说清楚。

它就是一个录屏软件吗？

按用途属于演示制作工具。底层核心是把结构化浏览器记录转成演示；浏览器画面和动作采集由 Playwright 等工具承担。它增加了步骤组织、可复用检查和重复生成的方式，普通录屏也能用于指导和备忘。

是 Agent 控制模型，加载内置浏览器后生成视频吗？

可以由 Agent 调用模型帮助规划，再调用浏览器工具操作，并交给 Specreel 输出视频。更准确的职责是“Agent 组织 → 模型提供规划或文案 → 工具控制浏览器 → Specreel 加工记录”。核心链路不强制需要 Agent 或模型，浏览器也不限定为聊天软件内置的那一个。

是不是不需要人参与？

准备好的流程在执行、采集、生成阶段可以不需要人逐步操作。定义目标、授权、处理验证码和异常、确认教程是否清楚或是否适合分享仍可能需要人。可选模型生成与修复能进一步自动化，但本项目没有证明任意任务全程零人工都能可靠完成。

操作备忘会保存我的想法和完整经验吗？

它主要保存执行了哪些步骤、画面如何变化以及选定检查的结果。为什么这样操作、背景是什么、得到哪些经验，需要另写说明。把这些说明关联到回放，才更接近完整的工作记录。

观看教程时，能继续操作真实业务吗？

回放中播放和“下一步”控制的是保存的步骤和画面。实际业务发生在原先录制浏览器执行时；要重新执行，需要重新运行脚本或在真实网站操作。

它会自动发现页面变化并把所有教程修好吗？

我们验证了改任务词后重新生成回放及更新标记。固定版本的更新签名主要来自步骤说明，不能据此保证识别所有视觉变化；控件和业务流程改变时，脚本可能需要维护。自然语言验证修复能力有源码，尚未在本项目实测完整闭环。
