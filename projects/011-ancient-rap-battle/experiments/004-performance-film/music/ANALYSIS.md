48 kHz 解码采样峰值约 **+0.0593 dBFS**，有 5 个浮点采样绝对值略高于 1；这不等于已经确认音频产生整数削波失真。建议最终成片从原 MP3 作恒定 **−1.5 dB** 音量调整，保留余量，不加压缩器或自动归一化。驱动参考也采用 −1.5 dB，最终只配回原曲，不能再把参考音频拼进成片或重复施加增益。

用立体声 10 毫秒 RMS 检查，未发现上一首曲子那种长达数秒的中间数字静音。低于 −50 dBFS 的连续区间约 91.86–94.61551 秒，低于 −70 dBFS 约 93.31 秒后，低于 −100 dBFS 约 94.10 秒后，主要是歌曲自然收尾。

## 更强本地模型复核

为提高争议唱词的核对可靠度，后续检查了项目和默认 Hugging Face 缓存，未发现已有 small。仅从 [Systran 官方模型仓库的固定版本](https://huggingface.co/Systran/faster-whisper-small/tree/536b0662742c02347bc0e980a01041f333bce120) 下载标准权重、配置、分词数据和模型卡；版本为 `536b0662742c02347bc0e980a01041f333bce120`，模型卡标明 MIT。模型仓库说明它是 OpenAI Whisper small 的 CTranslate2 格式转换；本地 CPU / int8 推理方式见 [faster-whisper 官方文档](https://github.com/SYSTRAN/faster-whisper#usage)。

总下载数据 486,214,370 bytes，其中 `model.bin` 为 483,546,902 bytes，SHA-256 为 `3e305921506d8872816023e4c273e75d2419fb89b24da97b4fe7bce14170d671`，与 Hub 提供的 LFS SHA 一致。权重放在 Git 忽略的 `work/model-cache/`；逐文件大小、SHA、来源、许可和固定版本保存在 `work/small-model-provenance.json`。没有执行下载的 Python 代码，没有启用 `trust_remote_code`，没有上传音乐，也没有付费调用。推理阶段显式禁用 Hub 网络，并只从本地目录加载。

顺序是先对 28–43、79–87、62–65.6 秒作独立无提示识别，再对同样三个窗口另存给定参考歌词的结果。base 原始结果没有覆盖。small 结果仍有同音错字，不能把模型的句首时间被拉到窗口开头当作精确起唱。

| 争议 | 无提示 small 证据 | 处理 |
|---|---|---|
| 杜甫参考第二句“鞋底…风霜” | 28–43 秒仍只识别出对应第一、第三、第四参考句的三个音节段；提示版也没找到第二句 | 保留未定位 / 可能漏唱，不加字幕，不捏造时间窗 |
| 合唱第一句“敬月光，也敬风霜” | 79–87 秒只给出接近“让这人间…听见回响”的音节轮廓 | 保留未定位 / 可能漏唱；未识别到本身不能证明绝对漏唱 |
| 桥段“这一笔，敬担当” | 62–65.6 秒识别为“这一辈情远方”，其中“远/方”概率约 0.923 / 0.945，与 base 的前句重复疑点一致 | 可能实际重复“这一杯，敬远方”；先不把“这一笔，敬担当”写入字幕，未声称人工听审确认 |

提示版出现了明显污染：收束窗口被硬识别成副歌词，多个字概率极低或长度为零；桥段在“这一杯，敬远方”后又挤入“这一笔，敬”残片。它说明给定参考文本可能影响模型输出，不能成为新增唱词的独立证据。三处继续留疑，驱动文件和完整原曲不变。

复核原文为 `work/new-song-asr-small-unprompted.json`、`work/new-song-asr-small-hinted.json`；独立审查记录为 `work/lyric-recheck-small.json`，已链接到歌词候选和音乐分析 JSON。另测三个争议窗口整体左右声道相关约 0.80–0.85，下混平均能量仅降低约 0.34–0.47 dB，未见全混音严重反相抵消；这不保证每个人声音素都清楚，也不构成人声分离或口型验收。
