# A01/A02 原片与原始参考音频的 tiny 转写对照

2026-10-15 使用本机已安装的 faster-whisper，以同一个 multilingual tiny 模型独立转写两条原片和各自原始参考音频。没有向模型提供歌词提示，没有调用付费服务，没有改动输入文件。

模型来自 [Systran/faster-whisper-tiny](https://huggingface.co/Systran/faster-whisper-tiny)，固定提交 `d90ca5fe260221311c53c58e660288d3deb8d356`，MIT 许可证。仅下载 CTranslate2 模型数据、配置和词表，约 78.2 MB，保存在忽略版本控制的 `work/model-cache`；未下载或执行远端 Python 代码。使用 CPU/int8、中文语言提示、beam size 5、temperature 0、无 VAD、无前文条件。完整模型文件 SHA-256 和运行参数见 `work/asr-review.json`。

| 输入 | tiny 原样识别文本 | avg_logprob | 最低词概率 |
|---|---|---|---|
| A01 原始参考 TTS | 就被一局 迎合到来捧场 | −0.540 | 0.236 |
| A01 生成原片音轨 | 就被一局 迎合到来捧场 | −0.684 | 0.281 |
| A02 原始参考 TTS | 你的工程中不下我的月光 | −0.450 | 0.188 |
| A02 生成原片音轨 | 你的工程装不下我的月光 | −0.393 | 0.555 |

`avg_logprob` 和词概率是模型内部指标，不能直接当作经过校准的识别准确率。tiny 对这些中文短句有明显同音字错误：预期 A01 是「酒杯一举，银河都来捧场」，预期 A02 是「你的工整，装不下我的月光」。原始参考音频本身就被识别错，因此不能把识别差异直接归因为生成服务改词。

A01 的原片和参考识别完全一致，支持两者语义一致的判断。A02 的原片和参考只出现「中 / 装」的不同，而原片识别出的「装」反而符合原始歌词。这份结果**没有检出明确改词证据，也不足以证明只有停顿被拉长**。结合已经观察到的音频活动区间差异，可以确认其时间组织有变化；微小改字、发音变化与细节仍需人工带声复核。

本次转写不证明口型精确，也不推翻 A02 原始音轨筛查失败。A02 的画面重定时仍是声学活动分组启发式，不是逐词或逐音素对齐。识别和词时间戳均有模型误差，不作为新的口型通过依据。

重跑已缓存模型，无网络请求：

```powershell
python -X utf8 scripts/asr-review.py
```

模型缓存缺失时，显式添加 `--allow-download` 才允许从上述固定版本下载四个数据文件。脚本每文件仅发一次请求，网络超时 20 秒、总下载预算 90 秒，失败不自动重试。原片及原始参考音频的读取前后 SHA-256 一致；完整分段、词时间戳、词概率、`no_speech_prob` 与识别文本均保留在 `work/asr-review.json`。
