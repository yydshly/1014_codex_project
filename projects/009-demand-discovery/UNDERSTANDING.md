# 009 · 从个人网站到需求发现工具：理解全景

整理与复核：2026-10-19。图中实际自动实验发生于 2026-10-15。本文对应[一张完整全景图](assets/understanding-map.svg)，保留这次对话从 JasonZhu.AI 出发的思考路径。

我们的核心理解：JasonZhu.AI 值得参考的，是把个人主页做成**研究与实践的沉淀、读者的引导入口、自己复习与更新的地方**。做之前回看，做之后记录，有反馈就更新，让经验持续服务下一次行动。

简要介绍可以概括为：**研究 → 实践 → 记录 → 展示 → 接触用户 → 获得反馈 → 更新研究。** 个人主页承载内容、案例、产品和下一步入口；通过实际触达和使用，继续修订研究。页面与源码本身不能证明获客或营收效果。

进一步向开发之前追问，会遇到“谁需要什么、为什么需要”的问题。009 由此扩展出需求发现工具：让 AI 从宽泛领域带回未预设的人群与问题线索，保存证据和发现路径，再进入验证与产品化。这是我们的产品探索方向，和直接借鉴个人主页的价值分层记录。

图例区分四种状态：**源库事实、我们的推导、本地实测、扩展假设**。发现管线跑通、需求成立、产品成立和商业化成立，需要不同证据。

| 能力 | 核查依据 | 对我们的启发 |
| --- | --- | --- |
| 内容与个人品牌 | 首页的文章、工具、项目和服务入口；固定版本的博客与中英文页面结构 | 把零散研究转成别人能理解、找到并继续阅读的资产 |
| 读者联系与承接 | 订阅、资料领取、联系及服务入口；README 的浏览、点赞、评论与管理模块说明 | 作品和内容可以接到下一步行动；真实获客、留存与收入效果需另查 |
| 自动快讯管线 | 固定版本存在 RSS / 网页采集、AI 筛选摘要、结构化保存、MDX 生成和定时提交发布代码 | 来源、AI 处理、保存、发布可以组成持续流程 |

## 2. 先学习个人主页，再向需求发现扩展

### 直接可以借鉴的三件事

| 对象 | 需要沉淀或引导什么 | 怎样进入下一次行动 |
| --- | --- | --- |
| 给自己 | 来源、固定版本、能力判断、实践结果、限制与下一步 | 开始相似项目时先查旧研究，检查哪些结论仍然成立 |
| 给读者 | 摘要、案例、方法、产品和明确入口 | 先理解你研究什么，再按兴趣继续阅读、看证据或体验工具 |
| 给后续反馈 | 使用条件、失败、复用和实际结果 | 新证据回来后修订记录，更新摘要与入口，让研究继续演进 |

入口引导需要说明“这里有什么”和“下一步可以做什么”。自己的主页可设置总览、研究专题、实践案例、方法清单、产品演示与真实联系入口。联系和转化需要明确实际提供的内容与服务；本研究页没有凭空添加联系方式、收款流程或客户见证。

复习放在具体节点：开始新项目之前回看，完成实践之后记录，得到用户反馈时修订，并按自己的节奏回顾长期未更新的判断。目标是让记录影响行动；更新日期、结论变化与下一步都应留下。

### 由这次学习引出的上游追问

这次对话的追问逐步上移：

1. 个人网站能展示研究、作品和能力，也可能成为接触用户的入口。
2. 对已有开发能力的人，仅有实现还不够，需要使用、反馈、优化和复用形成闭环。
3. 反馈之前还要找到具体人群；开发之前还要知道值得解决什么。
4. 到社区搜索一批问题，会受到搜索词、渠道和可读性限制。已有工具或格式词容易把选题带向熟悉区域。
5. 因此先观察活动，找到真实角色、共同任务、情境和约束，再从费力行为形成问题候选。
6. 用来源与反例修正候选，决定继续、收窄或搁置；之后才进入真实任务验证和产品实现。

这是我们结合自身情况的推导。没有证据可以仅凭现有对话认定“需求发现是你唯一或最大的短板”。009 先把这一环节做出来，观察它是否改善实际选题决策。

个人网站和需求发现工具分别承接不同环节：网站承载内容、案例、产品与触达；发现工具帮助寻找值得调查的对象。未来反馈可以回到新研究，研究成果又可以沉淀到个人网站。

## 3. 如何从不知道痛点开始

### 先发现群体

从经营、接单、创作、组织、维护、学习和交付等活动开始，问谁执行、谁确认、谁付款、谁承担结果。再用 **角色 × 共同任务 × 情境 × 约束** 细分。社区标签、任务分类、专业术语和工作教程帮助找到聚集地。

平台目录按证据价值组织：

| 入口类型 | 例子 | 主要观察什么 |
| --- | --- | --- |
| 社区与讨论 | Reddit、HN、Indie Hackers、小红书、知乎、V2EX | 谁在做什么、工作过程与求助 |
| 产品评价 | App Store、Google Play、G2、Capterra、Trustpilot | 哪种条件下失败、现有工具为何不适配 |
| 任务与预算 | Upwork、Fiverr、Freelancer、闲鱼 | 交付要求、付出的成本、预算意向 |
| 技术与维护 | GitHub Issues、Stack Exchange | 复现、脚本、维护和返工 |
| 垂直业务 | Shopify 社区和应用商店、WordPress、Etsy | 同类角色的专业任务与替代流程 |
| 趋势与内容 | Product Hunt、AppSumo、Google Trends、YouTube、抖音、Bilibili | 变化、新用语与候选人群 |

27 个入口是目录，未全部接入自动采集。预算意向不等于成交，趋势热度不等于市场规模；索引覆盖与账号发言也会影响我们看到的人群。读取条件、授权范围、失败和缺失必须保留。[完整来源目录](SOURCES.md)

### 再发现可调查的问题

问题候选写成：**谁，在什么情境，要完成什么任务，遇到什么障碍，已经付出什么代价。**

观察八类行为：反复手工处理、工具间补缝、付费请人做事、等待与催促、重复错误与返工、工具不适配、缩减目标或放弃、变化新增负担。AI 需要读上下文，区分发帖者和回复者，了解工作过程，而不只找“痛点”“难用”等情绪词。

按任务、情境与障碍聚合；PDF、邮件、表格和 AI 只是对象词，同一个对象可能服务不同目标。寻找工作顺利的人和已经奏效的办法，也可能发现不值得再做新软件的原因。

### 让证据推动下一问

七步循环：**设定边界 → 发现角色 → 观察行为 → 问题假设 → 独立证据与反例 → 研究判断 → 修正下一轮。**

AI 可以从原文扩展业务术语、搜索相邻场景、连接类似任务、提出其他解释，并说明哪条新线索引出了下一轮查询。保存公开动作与决策摘要即可，不需要展示模型内部推理。人工负责复核材料、调整范围和选择验证行动。

四层证据分别是：找到材料；看到某人的具体障碍；形成独立重复模式并核对反例；取得真实任务、试用、复用或交易的行为验证。不同层次不能相互替代。

### 实验 001：从宽泛领域到具体角色与判断

2026-10-15 输入“小型本地服务经营”，英语市场，个人可做网页工具；未指定清洁、擦窗、汽车精洗或排班。官方 Codex 正常本机登录调用 OpenAI，约 5 分 7 秒完成三阶段。

- 发现 3 类角色：住宅清洁公司排班负责人、兼职上门汽车精洗经营者、保留本职工作的早期擦窗经营者。
- 沿实际来源选择清洁公司的周期安排继续调查；后续追问继承上一轮线索。
- 周期排班的剩余人工协调：**优先核实并收窄**，因为固定周期、地区分组等已有有效反例。
- 临近取消后的空档处理：**有条件继续调查**，要区分协调困难与没有可接单客户。
- 天气、病假取消后的补约：**暂时搁置**，主要证据指向可工作时间不足。

实际记录为 **3 类人群、3 个候选、10 条来源链接、5 次检索调用、6 次页面打开动作**。6 条来源可关联打开动作，另 4 条待核查；本地独立逐字核验成功 **0 条**。工具打开动作不等于全文读取成功。程序保留了这些差异，没有把链接或模型摘录升级为独立核验。

身份独立性、讨论的当前有效性、跨领域效果、市场规模和付费仍未验证。一次管线运行可以说明“系统能够开始发现”，不能说明“这些候选已经值得开发”。[实验全文与十条原始链接](EXPERIMENT-001.md) · [结构化快照](data/discovery-latest.json)

## 5. 可扩展价值与推进条件

| 扩展 | 预期帮助 | 应先取得的证据 |
| --- | --- | --- |
| 来源与覆盖 | 多语言、多渠道、垂直行业的发现 | 能读上下文，确实增加新角色或独立材料 |
| 持续观察 | 区分一次抱怨与反复发生，跟踪变化 | 新证据会改变判断，来源更新有用 |
| 机会研究 | 对比竞品、工作流、约束和可做切口 | 明确已有办法的剩余缺口，个人能处理关键任务 |
| 需求验证 | 用访谈、真实任务和小实验核实 | 目标人群提供可复核经历，出现试用、复用或支付行为 |
| 产品落地 | 把一个障碍实现成最小网页工具 | 任务结果改善，使用者能完成并愿意继续使用 |
| 商业化 | 专题情报、研究工作台、垂直研究服务 | 确定客户、持续价值、可控成本、真实复用或交易 |

最先服务我们自己的选题，而后验证其他独立开发者是否存在相同需求。服务更多人群、做 SaaS 或收订阅费用，均是待验证方向。出海还要核实当地任务语境、触达渠道、语言和支付条件，不能仅凭英文来源推断国际市场成立。

个人研究与主页沉淀的完整路径：**研究 → 实践 → 记录 → 展示 → 接触用户 → 获得反馈 → 更新研究。**

产品扩展闭环：**发现人群与问题 → 追查与筛选 → 真实任务验证 → 最小产品 → 使用与反馈 → 个人网站展示与触达 → 新观察。**

真正的价值是减少凭感觉做产品的次数，更早停止不合适方向，把线索、判断和验证结果变成可复用资产。衡量有效性应看新增独立证据、决策变化、人工复核与调用成本、真实任务改善、复用与交易，而不只看抓了多少条数据。
