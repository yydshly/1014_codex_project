## 1. 思考从哪里来

起点是 [JasonZhu.AI](https://jasonzhu.ai/) 个人网站与独立开发内容。004 研究了作品展示、案例写作、推广入口、需求定位与用户反馈的连接。参考仓库为 [zhuyansen/jasonzhu.ai](https://github.com/zhuyansen/jasonzhu.ai)，固定版本 `9780c4408227e9b0bace1b1e2ed5160f341f2753`。该版本 README 标注“Private project. All rights reserved.”，本项目没有复制其代码或图片。

原站相关文章与此前分析见 [004/RESEARCH.md](../004-jasonzhu-ai/RESEARCH.md)。其中关于独立开发复盘、推广、工具渠道与个人网站的内容，是方法线索，不能推导出本项目的商业结果。

讨论逐层推进：

1. 个人网站对我们有什么价值？研究成果可以长期保存、展示能力，并成为接触使用者的入口。
2. 已经能实现产品，为什么还缺少闭环？还需要具体使用者、反馈、复用与交易证据。
3. 最难的环节是什么？在开发之前，发现问题和需求。
4. 去哪里找？Reddit、评论、任务市场及其他人群活动场所。
5. 搜到一些问题是否足够？搜索词和已有产品会影响采样，可能一直得到文档、格式或整理类题目。
6. 真正应研究什么？在不知道具体痛点、甚至不知道关注谁时，怎样发现人群并观察问题。
7. 可以形成什么产品？平台地图 → AI 主动探索与问题证据 → 机会判断、需求验证与落地扩展。

平台地图、行为信号、AI 追查循环和产品规划属于我们的分析。没有证据表明原个人网站具备这些自动化能力，也不把其链接的其他项目能力计入原站。

## 2. 研究对象与核心问题

目标是从真实活动中识别一群人的共同任务、反复费力的步骤和已付出的代价，再判断是否值得继续调查。

> 谁，在什么情境，想完成什么任务，遇到什么障碍，已经付出什么代价？

代价可以是时间、费用、等待、错误、返工或放弃。没有原文支持的频率、耗时和预算须保留为未知。需求候选仍需真实任务、访谈、试用与交易等后续证据。

## 3. 怎样发现人群

没有明确领域时，可以先观察经营、接单、制作内容、组织活动、维护系统、学习或交付作品等活动。它们是探索入口，并非本次已验证的产品机会。

AI 提出可能涉及的角色，再寻找证明角色实际在做某件事的材料。例如交付作品涉及创作者、工作室负责人、客户项目经理；继续从材料中识别谁承担哪些步骤、怎样协作。

人群可用“角色 × 共同任务 × 情境 × 约束”描述：

- 角色与责任：执行者、审核者、经营者、维护者。
- 任务：核对、交付、比较、安排、更新、确认、迁移。
- 情境：业务阶段、协作方式、发生频率、交接节点。
- 约束：语言、设备、时间、技能、权限、数据与预算。

“自由职业者”只是大类；“按项目收费、同时向多个客户交付作品的独立工作者”接近可观察情境，但仍需来源核实。

社区分组、问答标签、软件分类、外包任务与教程可帮助定位聚集地。选择渠道时说明：为什么这里可能出现该角色、什么内容支持这一判断、哪些人没有发言。人群不必围绕“创业”或“AI 工具”聚集。

## 4. 如何从行为发现问题

| 线索 | 需要追问 | 常见误判 |
| --- | --- | --- |
| 反复手工处理 | 为什么重复、多久发生、哪一步需人补上 | 有重复就认定需要新软件 |
| 工具间补缝 | 信息在哪次交接丢失、谁重新整理 | 工具多就认定流程差 |
| 付费外包 | 预算购买判断、责任还是操作，任务能否标准化 | 报价当成交，一次定制当订阅 |
| 等待与催促 | 谁缺什么信息、等待影响什么结果 | 权责和组织问题都当软件机会 |
| 重复错误与返工 | 错误在哪里产生、怎样发现、如何补救 | 混淆偶发故障、培训不足与系统性障碍 |
| 现有工具不适配 | 哪项约束导致任务失败、影响哪些角色 | 单个功能请求当独立产品市场 |
| 缩减目标或放弃 | 结果原本是否重要、为什么没继续 | 把低优先级当强烈未满足需求 |
| 变化带来负担 | 新规则、规模或工具变化让谁多做什么 | 热度或短期迁移当长期需求 |

情绪词可帮助发现线索，但要继续读具体经历。描述工作方法、展示表格、解释补救步骤的人，可能没有直接说“痛点”。

## 5. AI 如何主动探索

三种起点：未知人群时从活动地图开始；已有大致人群时按任务、情境和约束细分；已有产品时从使用经历反推角色，再到其他地方追查。

七步循环：

1. **圈定边界**：语言、市场、可选领域、实现约束、材料与调用预算、停止条件。
2. **发现角色**：通过真实来源核对谁在做什么，建立角色与渠道对应关系。
3. **观察行为**：保存工作过程、求助、评论和任务中的具体行为。
4. **提出假设**：写清人群、情境、任务、障碍、代价与其他可能解释。
5. **找独立证据与反例**：使用真实术语扩词，到相邻社区或其他来源核对。
6. **筛选研究价值**：继续、转向或搁置，保留理由和未知项。
7. **修正下一轮探索**：根据新增事实决定看谁、查什么、何时停止。

关键在于调查随观察改变。固定检索词批量搜帖只完成其中一部分；研究产品需要留下发起下一轮查询的原因。

初始搜索可围绕角色、任务、过程、结果、约束与替代做法。英文表达示例：`my workflow`、`how do you manage`、`keep track`、`every week`、`manually`、`waiting for approval`。示例只用于启动，不能限定问题范围。

后续从原文提取对象、工具、角色、业务术语与触发条件。例如追查“核对”的对象是版本、数量、规格还是平台要求；不同对象可能指向不同群体。

应寻找工作顺利的人、有效流程和不需要新工具的原因。只找支持假设的材料容易累积确认偏差。

## 6. 多来源怎样互相核对

- 社区与教程：发现角色、任务和工作过程。
- 评论与支持论坛：观察使用条件、障碍和补救。
- 外包任务：观察交付要求、技能组合和预算意向。
- 技术问答与问题跟踪：观察复现、脚本和维护成本。
- 趋势与新产品：发现术语、变化与候选人群，继续找实际经历。

不能把抱怨、差评和预算机械相加成机会分数。先确认是否属于相同角色、任务与情境；来源也可能互相矛盾。

目录含 27 个入口，分为官方说明已核查、入口已核查与待核查。公开页面、索引覆盖、官方 API 与商业用途许可分别记录。

第一轮可比较两条路线：公开接口有助于测试采集和上下文保存，但 HN / GitHub / Stack Exchange 偏技术人群；垂直业务路线维持角色与任务一致，但需逐源确认数据获取条件。选择取决于研究目的。

## 7. 证据与聚合规则

四层证据：找到材料 → 看到具体障碍 → 发现独立重复模式与反例 → 取得真实任务、试用、复用或交易验证。前一层不能替代后一层。

每条材料保留平台、原 URL、对象标识、标题、角色、原话、位置、读取时间、发布日期依据、正文/回复关系、完整度、访问方式和失败状态。

每个问题簇保留角色、任务、情境、障碍、代价、支持来源、独立性、反例、现有办法、解释、关键未知、下一步和判断。

优先按“任务 + 情境 + 障碍”聚合。不能只按 PDF、表格、AI 或邮件等对象词合并，相同对象可能对应不同目标。

同帖 URL 变体先归一；转载、引用和同一人的重复表达不视为新独立用户。分清发帖者与回复者，识别推广与模板内容。保留缺失、删改与失效，不能让采集成功的样本冒充全部讨论。

网页中 12 / 24 / 40 条材料是工作与成本上限，不是统计充分性的标准。停止时报告采样范围和不足。

## 8. 已有样本带来的反思

两条材料采集于 2026-10-15，来自当前会话联网检索与页面读取。仅为可读页面片段，绝对发布日期未知。本地 Reddit JSON 曾返回 403；009 未重新抓取或运行独立模型 API。

它们能帮助解释证据和已有办法，却不能证明已实现从未知问题开始的自动探索。最初为什么选择设计师、忽略了谁、作者独立性、问题频率与现有办法效果尚未全面核实。

004 之前的 20 条来源受搜索词、渠道和可读性影响，结果偏文档和交付。下一轮需要记录探索起点、拓展不同活动，并观察偏差是否减少。

## 9. 如何衡量工具是否有用

- 能否从活动范围带回未预设的具体角色和任务。
- 候选是否具有可读原文、上下文和清楚的发现路径。
- 新增材料是否来自独立经历，而非重复传播。
- 是否找到足以改变判断的反例或已有办法。
- 使用者是否据此缩小方向、调整假设或有依据地搁置。
- 人工复核工作、外部调用成本与有效线索的关系。
- 后续接触目标使用者时，候选描述与真实经历是否一致。

以上是拟衡量的维度。一次真实自动探索已记录在实验001；尚无跨领域效果或商业指标。
