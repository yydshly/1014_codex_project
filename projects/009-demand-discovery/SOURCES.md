# 需求发现平台与来源说明

核查日期：2026-10-15。结构化目录见 [data/platforms.json](data/platforms.json)。

009已增加通过OpenAI联网工具执行的本地自动探索，实测见 [实验001](EXPERIMENT-001.md)。这不等于本目录的27个平台均已接通专属接口。

本目录收录 **27 个研究入口**，用于回答“去哪里观察人群、任务和费力行为”。它不是已经采集好的需求数据集，也不是已经接通的 27 个数据源。目录里的观察角度、发现问题、信号标签和偏差提醒，均为本项目的研究判断；不代表平台承诺这些信号能够证明需求。

## 目录覆盖什么

| 类型 | 数量 | 适合寻找的线索 |
| --- | ---: | --- |
| 人群讨论 | 6 | 社区分组、工作过程、求助、追问、临时应对 |
| 软件与应用评论 | 5 | 已有产品使用后的障碍、具体使用条件、替代动机 |
| 外包与付费服务 | 4 | 有人出预算委托的工作、交付要求、服务细分 |
| 开发者问题 | 2 | 问题复现、功能请求、相似脚本和技术绕行 |
| 垂直生态 | 4 | 某类从业者在同一业务系统中的具体流程 |
| 趋势与内容 | 6 | 教程步骤、新任务词、新产品面向的人群 |

海外入口用于探索英语市场，中文入口用于补充人群和场景认知。两种市场必须分别收集证据，不能把国内发现直接当作海外需求。

分类按研究用途划分，存在交叉。例如 Shopify App Store 也属于评论来源，AppSumo 也包含评论与购买问答。当前分类帮助浏览，不代表来源只能用于一件事。

## 如何阅读核查状态

- **官方说明已核查（official_checked，15 个）**：查阅了官方文档、官方功能说明或官方索引内容，能够支持目录中相应的能力与限制。没有因此获得数据权限，也没有在本项目中运行接口。
- **入口已核查（entry_checked，8 个）**：本次能够读取官方入口、分类或导航；内容覆盖、批量获取、商业再使用条件没有核查完成。
- **待核查（pending，4 个）**：本次读取遭遇超时、安全验证、空正文或浏览器提示。保留研究建议，不能声称已读取帖子、视频或评论。

JSON 的 access 是建议的接入路线，不是接入成功状态：

| 值 | 含义 | 需要继续确认的事 |
| --- | --- | --- |
| public_api | 已找到公开数据读取的官方接口文档 | 方法、认证、限流、历史覆盖、数据许可；仍未接入 |
| authorized | 已找到需要凭据、账户权限或使用许可的官方能力 | 实际授权范围、可访问对象和商业用途 |
| search_or_manual | 先通过可用搜索索引或人工研究公开材料 | 原文是否可读、结果覆盖、完整性与再使用条件 |
| manual | 当前只作为人工研究候选入口 | 登录与访问条件、内容范围；不承诺自动化 |

“网页可见”“搜索能搜到”“存在 API”是三种不同事实。搜索摘要不是完整原文；官方接口存在也不代表允许访问所有对象或用于任意商业产品。

## 这些来源怎样配合发现问题

以下是本项目提出的研究路径，尚未运行成自动化产品：

1. **活动 → 人群**：先选活动而不预设痛点，例如经营店铺、交付设计、制作课程。社区、教程和垂直论坛帮助识别角色、阶段与共同任务。
2. **过程 → 障碍**：寻找反复核对、等待、复制、催促、拼接多个工具、请人补工作、缩减目标等行为。必须记录原文语境，不能只抓“难用”等情绪词。
3. **线索 → 下一轮探索**：使用真实材料中的角色名、任务词、对象、限制条件和工具名扩展搜索；让新证据改变调查方向。
4. **不同来源 → 独立核对**：社区中的任务障碍，在评论里查现有方案，在外包任务里查是否有预算意向，再找“不遇到这个问题的人”作为反例。
5. **重复证据 → 候选**：按具体人群、任务、触发条件和障碍聚合，保留独立来源数量、日期与未知项，输出待调查问题。

不能把“社区抱怨 + 差评 + 一条外包报价”机械相加成机会分数。它们可能指向不同人群、不同任务，甚至互相矛盾。需要能解释证据之间的联系。

第一轮无需接入全部来源。可优先比较两条路线：

- **公开接口实验**：HN、GitHub Issues、Stack Exchange 的接入条件相对明确，用于验证自动取数、上下文保存和追踪线索；样本明显偏技术人群。
- **垂直问题实验**：先选一个业务生态，人工与可用索引观察社区，再用评论和外包任务补证；有助于保持人群与任务一致，但数据接入需要逐源核查。

## 同类产品参考

[**PainOnSocial**](https://painonsocial.com/) 官网展示了按 Reddit 社区进行痛点分析，并给出引文与来源链接的产品思路。本次只核查官方描述，未注册测试其采集覆盖、评分效果、输出准确性或商业表现。

可以借鉴“结论能够回到原文”的表达方式。待验证的差异化方向是：由活动发现人群、按线索继续探索、保存反例、使用不同来源核对，以及展示为什么淘汰某个候选。不能根据同类官网的营销描述推断市场已被验证。

## 后续接入与来源维护

每增加一个真实采集器，应独立记录：

- 使用的官方入口、接口版本或授权方式、用途与限制。
- 本次实际查询、可读范围、失败或缺失情况；时间未知时明确标注。
- 原始 URL、对象标识、采集时间、正文与回复的来源边界。
- 原文片段、推断、反例和待确认项，分别保存。
- 去重规则及相同原始材料的转载关系，避免把重复传播当作独立需求。
- 内容删除、更正、失效与许可变化时的处理方式。

平台能力与规则会变化，核查日期只是一次观察。本目录没有接通这些平台的专属采集器或实现全量覆盖。新增的OpenAI本机自动探索另见实验001；平台目录本身没有验证任何具体产品的需求与付费意愿。
