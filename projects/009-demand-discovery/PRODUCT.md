# 009 · 需求发现工具：产品思路与扩展

整理日期：2026-10-15。本文件是产品规划；当前已实现能力见第 9 节，规划能力不代表已经上线。

## 1. 产品定位

前置学习是个人主页的研究沉淀、入口引导与复习更新，形成“研究 → 实践 → 记录 → 展示 → 接触用户 → 获得反馈 → 更新研究”的过程。需求发现工具是其上游扩展方向；个人主页继续承载方法、案例、产品与触达，二者通过真实任务和反馈连接。

帮助有开发能力、却缺少稳定选题依据的独立开发者，从真实活动中发现人群、任务与问题，积累可追溯的证据，再决定下一步调查什么。

目标用户和价值需要验证。第一位使用者是我们自己，先在实际项目选择中观察工具是否能减少无效搜索、发现未预设的人群，或帮助有依据地停止一个方向。

## 2. 三层结构

| 层次 | 用户的问题 | 产品产物 |
| --- | --- | --- |
| 来源层 | 去哪里观察人群、任务与代价？ | 平台地图、角色聚集地、接入条件与采样范围 |
| 发现层 | 怎样从不知道痛点的状态开始？ | 角色与任务地图、行为线索、问题候选、证据和发现路径 |
| 扩展层 | 值得继续做什么，怎样验证和落地？ | 机会判断、访谈与验证实验、最小产品说明、反馈与演进 |

第一版优先验证发现层。来源接入为调查服务，新增平台应带来独立证据或新角色，而非单纯增加数量。

## 3. 用户输入与核心流程

### 输入

必要的探索边界：语言、市场、可接受的研究成本、产品实现边界。领域、人群与竞品均可选；没有人群时先发现角色。

### 网页路径

1. 建立探索项目，说明任务与停止条件。
2. 查看 AI 提出的角色和任务地图，逐项查看来源依据。
3. 沿工作过程看到行为线索，提出具体问题与其他解释。
4. 查看下一轮查询及发起理由，允许人工调整调查方向。
5. 查看问题簇的支持、反例、现有办法和未知。
6. 选择继续研究、进入访谈或搁置，保存依据。

产品需要展示过程：为什么关注某角色，哪条原话引出新问题，为什么转向或淘汰。只有最终痛点列表会隐藏采样与推断过程。

### 三种启动模式

- **开放探索**：从活动范围寻找角色，再通过真实来源核对。
- **人群探索**：把宽泛角色拆成任务、业务阶段、协作与约束。
- **产品探索**：从评论或使用经历定位受影响情境，再到其他来源追查。

## 4. MVP 的最小闭环

第一轮无需接入全部来源。选择一个可取得上下文的来源与一类活动，保留真实研究过程：

探索边界 → 角色候选 → 观察材料 → 行为线索 → 问题假设 → 后续调查 → 支持与反例 → 人工复核。

### 核心验收

- 使用者没有输入具体痛点，也能产出带来源的具体人群与问题候选。
- 能解释最初为什么选择该人群，以及新证据如何改变下一轮查询。
- 原话能回到实际材料，正文和回复的角色清楚。
- 去重和独立性有依据；不把转载当新增用户。
- 找到已有有效办法时保留，允许给出“暂不值得做”的结果。
- 读不到、材料不足、预算结束或调用失败时准确报告。
- 结论明确区分事实、解释、假设和未知。

某个例子成功只代表一次探索完成，不代表对所有行业有效。后续需对不同活动重复研究，并记录失败类型。

## 5. 未来系统与数据对象

建议分离来源接入、原始材料、AI 调查、证据聚合与网页复核。采集失败不能伪装为分析完成，分析完成也不能标为市场验证完成。

| 对象 | 关键字段 |
| --- | --- |
| 研究项目 | 市场、语言、范围、角色假设、预算、停止条件、状态 |
| 来源配置 | 平台、官方入口、授权范围、用途限制、配额与核查时间 |
| 探索动作 | 原因、输入线索、查询、目标渠道、结果与失败 |
| 原始材料 | URL、对象标识、文本、角色、原文位置、时间依据、完整度 |
| 人群假设 | 角色、任务、情境、约束、聚集地、支持材料与未知 |
| 行为线索 | 任务步骤、原话、代价、解释、相关人群 |
| 问题候选 | 任务、情境、障碍、支持、反例、现有办法、独立性 |
| 研究判断 | 继续 / 转向 / 搁置、理由、证据版本、下一步 |
| 验证实验 | 访谈、试用、复用、交易结果与适用条件 |

最初可用简单存储承载，不预设必须引入向量库、知识图谱或多代理架构。只有检索、规模或协作需求出现时再增加复杂度。

### 接入原则

官方允许的数据接口、授权导入、可用搜索索引和人工整理都可作为输入方式，逐源记录实际范围。搜索负责找到候选链接，读取负责取得上下文；索引不能保证完整覆盖。

后续独立服务需要自己的模型与搜索访问配置。当前会话的联网工具不自动等于网页产品的可调用接口。API 与账号能力应在实际环境验证，不复用桌面登录凭据。

### 运行边界

限制查询数、材料量、调用成本与循环轮次；原始文本中的指令作为外部内容处理。保存错误与停止原因，支持中断、重新研究和结果版本比较。联系使用者、发布内容和交易应作为另外的明确动作。

## 6. 核心页面

| 页面 | 主要任务 |
| --- | --- |
| 平台地图 | 找研究入口、看接入条件和偏差，加入探索项目 |
| 探索项目 | 输入边界、调整角色假设、查看运行与覆盖状态 |
| 人群地图 | 浏览具体角色、共同任务、情境与来源 |
| 发现路径 | 查看每轮观察、追问和转向理由 |
| 问题候选 | 查看原文、支持、反例、现有办法、未知和下一步 |
| 研究记录 | 保存复核、导出证据、比较版本与实验结果 |

当前 009 把上述方法放在一份研究网页中；未来产品可在实际使用后再拆分页面。

## 7. 差异化需要怎样验证

[PainOnSocial](https://painonsocial.com/) 官网已介绍社区选择、AI 痛点分析、原话和来源链接。本项目仅核查官网描述，未实测其效果，也不能从营销信息判断其客户数或商业成立。

可验证的差异化假设：

1. 能从活动发现用户之前没想到的细分人群。
2. 调查会由证据改变方向，过程可回溯。
3. 不同来源围绕同一任务核对，保留矛盾与未知。
4. 发现现有办法已经够用时，帮助使用者停止。
5. 研究成果能进入访谈和真实任务验证，得到后续反馈。

验证方式是与使用者原有研究过程比较：是否减少工作、是否改变判断、材料是否可信，以及是否愿意持续使用。没有实验前不声称效果更好。

## 8. 扩展方向、条件与衡量

### 扩展来源与行业

添加语言、行业论坛、评论和任务来源。条件是接入可用、用途清楚，并增加独立证据。衡量新人群、新情境、结论变化及有效线索成本。

### 持续观察

保留研究项目，增量检测旧问题、新约束与解决办法变化。条件是去重、失效与删除处理可用。衡量真正影响判断的更新，避免重复推送。

### 机会判断

研究已有流程、产品覆盖、价格资料和开发边界。条件是支持与反例充分；竞品资料注明时间。衡量使用者是否能缩小、调整或放弃方向。

### 需求验证

生成访谈提纲、研究招募入口、试用任务与验证页面。条件是具体问题已清楚；联系与实验由使用者安排。衡量实际经历、任务完成、复用与交易。

### 产品落地

把验证后的问题转为需求说明、最小功能、演示和反馈计划。条件是范围与成功标准可解释。衡量目标任务完成情况，而非生成代码量。

### 可能的收费方式

个人研究工具、专题问题库/简报、团队工作台、人工加 AI 的研究服务。先观察研究任务频率、交付预期与持续增量，再测试额度、订阅或单次交付。价格、收入与留存均待验证。
