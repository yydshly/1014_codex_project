## 0.4.0 同一场景里的随机内容

## 0.3.0 连续开门

验证日期为 2026-10-15。用户流程是未知门入口 → 随机揭晓 → 参与当次遭遇 → 下一扇门，或从手记回访已经发生的经历。应用仅在浏览器本地运行，无 API 或外部数据服务；存储链路为动作 → 状态规则 → 本地存储 → 场景与文字更新。

### 实际浏览器结果

使用内置浏览器的桌面侧栏视口走完一轮，实际顺序为：海边候车亭、打烊前的邮局、旧星图观测台、风过的天台、老街修补铺、漂浮温室。六次标题与内容各不相同，进入前只显示门前线索。

| 检查 | 实际观察 |
| --- | --- |
| 安静两次 | 候车亭自然出现船灯，坐下与接雨状态可切换；天台自然起风，正在输入的纸签及焦点未丢失，提交后原句挂入场景 |
| 故事两次 | 选择“有点想家”后文字写入明信片并盖邮戳；修补铺可听来历、挑旧铃、转动发条，出现木鸟动作与对应文字 |
| 两种挑战 | 星环按可见方向转动后归位、连线；温室 A 转动后光线改变，回访再转 B，植物展开 |
| 未完成进度回访 | 温室转过 A 后离开，从手记返回；对比 SVG 光线路径与离开前一致，再完成 B，无布局重抽 |
| 故事后续 | 从手记回邮局，看到“后来给家里打了电话”的对应后续，并保留当时写下的句子 |
| 刷新 | 邮局后续、原句及六条手记仍在，没有重演初次相遇 |
| 手记 | 列出六种实际去过的遭遇、各自行动痕迹，以及温室的特别留住标记，不列出未去过的目的地 |
| 运行日志 | 浏览器控制台未报告错误或警告；铃声的主观听感仍由用户体验判断 |

## 0.2.0 效果与构图

在实际 `797 × 903` 的桌面侧栏窗口中发现，原先只按移动端断点调整构图，会使手掌和水盘靠近或超出右侧边缘。现改为按画面比例连续调整相机位置与视野，并在接雨时轻微引导视线。此窗口内已实际检查站立、坐下和接雨，掌心、水滴接触点及水盘均可见。

本轮同时加入方向波、天空反射和缓慢移动的云层；调整湿木地板的明暗；以带指节的手掌和连续衣袖替换原先简化的手部；船只、船灯光晕与水面倒影共同淡入淡出。黄昏坐姿接雨及船灯的当前画面见 `assets/preview.jpg`。

三种天气在此窗口中均已重新检查：夜雨仍有可辨的海面波纹，雨后移除空中降雨并保留檐水。按住 R 接雨、松开后收手的状态正常；黄昏提前预览船灯可见。浏览器控制台未报告错误或警告。

## 适用范围

该原型为本地运行的程序化 3D 场景。当前实际交互验证覆盖桌面浏览器，竖屏比例另有相机投影测试；移动设备的触控与性能仍待实机体验。没有后端、外部模型服务或素材请求，收藏仅写入当前浏览器的本地存储。

这些检查确认功能链路可运行，不证明场景一定使人放松或愿意回访。是否愿意停留、自然等待和再次开门，需要结合实际体验反馈判断。
