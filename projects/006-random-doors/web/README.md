# 随机门 Web 原型

当前版本 `0.8.0` 包含世界与身份实验、网页研究总览与保留的 `0.5` 连续开门原型。新入口 `worlds.html` 把随机不同世界与不同身份接入玩法：隐身完成任务、附身猫或列车长、成为创世主改写法则。三世界八身份、任务与局部条件按相容配置选择，进入后保持规则稳定；行动与结果可在身份见闻中回访。详见 [设计说明](../WORLD_IDENTITIES.md)。

原连续开门原型：原型实现两层随机：开门选择地点，到达后遇见该地点中的一种处境、事件或布局。安静、故事、挑战各有两处地点，同一地点也会发生不同的事。入口与六处地点使用统一的原画场景，人物、雨、船灯、信件和机关通过独立图层与动作状态呈现。原画在制作时由内置 ImageGen 生成，运行时随页面从本地加载。

线上地址：[研究总览](https://yydshly.github.io/1014_codex_project/006-random-doors/research.html) · [连续开门](https://yydshly.github.io/1014_codex_project/006-random-doors/) · [3D 候车亭](https://yydshly.github.io/1014_codex_project/006-random-doors/seaside.html)。2026-10-16 已验证，记录见 [deployment.json](../deployment.json)。

环境要求为 Node.js 22.12 或更高版本。在本目录执行：


也可以执行 `npm ci`，再执行 `npm run dev`。打开 [连续开门原型](http://127.0.0.1:4178/1014_codex_project/006-random-doors/)。服务只监听本机，端口为 `4178`。

## 世界与身份怎么体验

打开 `worlds.html`，点击“推开未知的门”。也可以在“想先试一个特定世界”里只指定世界，身份仍由偶然决定；`?world=museum`、`train` 或 `genesis` 只选择世界，不提供固定身份或作弊状态。

| 世界 | 操作 |
| --- | --- |
| 隐身博物馆 | 点击相邻地砖，或使用方向键/WASD/画面方向键；准备静步或影跃，等待避开守卫；靠近目标触碰，再返回左下角出口 |
| 附身列车 | 切换车厢，或用能力按钮前往线索地点，再次点击取得线索；与乘客互动，辨认并归还失物 |
| 创世规则 | 选一条有权限的法则，推进一刻观察后果；可以修改比较，最后留下规则；未达成愿望的结果会如实标记 |

“同一世界，换个身份”保留世界种子，创建新的身份经历，目标随能力适配。身份见闻保存最近 40 次状态；未完成也可离开。刷新保留正在经历的内容，不重抽身份、任务或已经准备的随机门。新原型使用独立本地存储键，不影响旧偶遇手记。世界内图形为原创 HTML/CSS/SVG；门前复用已登记的本地原画，没有新增依赖或外部模型调用。

## 原连续开门怎么体验

1. 保持“全部交给偶然”，先听门前的一点线索，再推门。
2. 进去后按眼前的内容观察、回应或操作，没有必须完成的任务。
3. 点击“走向下一扇门”，回到一个尚未揭晓的入口，再次推门。
4. 打开“遇见手记”，回到任意去过的那一次。纸签、故事选择、镜子和星环进度会保留。
5. 想比较同一场景的变化，点“同一场景，再遇见一次”；在邮局中点“邮局里，再遇见一个人”。这会创建新的遇见，旧的经历仍在手记里。

| 范围 | 两处可去的地点 | 可参与的动作 |
| --- | --- | --- |
| 安静停留 | 海边候车亭、风过的天台 | 坐下、接雨、等待船灯；写或留白一张纸签、碰风铃、等一阵风 |
| 参与故事 | 打烊前的邮局、老街修补铺 | 陪旅人写信并投递；听店主讲来历、挑铃并转动木鸟发条 |
| 完成小挑战 | 漂浮温室、旧星图观测台 | 转动两面镜子让光抵达植物；转动三道星环让亮星与空星重合 |

邮局现有六位人物与六种心事，各有三个专属回应、信件和后续；修补铺有三种选铃处境，候车亭与天台各有三种自然变化，温室有六条可解光路，星环目标和初始方位按种子变化。具体内容见 [同场景变化](../VARIATIONS.md)。

船灯与天台起风在进入后自然等待 10 至 16 秒出现，用较短的等待验证整条连续流程。用户可以继续停留，不设两分钟自动退出。风铃和木鸟的短铃声仅在用户主动触碰或转动发条后播放，关键反馈同时由画面和文字提供。

“特别留住”会给手记加一个记号；普通经历也会自动保留。手记仅写入当前浏览器，刷新不会更换正在经历的内容；没有后端、账号或外部模型调用。14 张 WebP 原画合计约 2.97 MB，随项目本地提供，开门前预载当前候选所需的场景和人物。

## 随机规则

- 默认从六个遭遇中抽取未经历的候选，走完本轮再补回；条件允许时也避开刚开过的类别。
- 只选择一种范围时，在该范围的两个遭遇中先各经历一次，再循环。
- 门前选好候选与种子，刷新不重抽；进门后人物、布局和已发生的事保持稳定。
- 用户动作由固定规则产生反馈。解题成功、人物的回应都不再次抽概率。
- 地点内的内容另有候选池，先经历完当前内容再补回；同一场景连续新遇见时尽量避开刚才的内容。
- 温室有六条可解光路，星环的目标与起始位置按种子确定。人物、心事、回应和回访后续成套选取，动作之后不再抽签决定结果。
- 回访不消耗已经准备好的下一扇随机门，也不会重置未完成的题或已选的回应。
- 旧版手记升级后保留原人物、信件、自然事件与光路，不会被新随机内容替换。

具体内容和验证目标见 [连续开门设计](../RANDOM_LOOP.md)。这是有限内容池中的随机选择，不宣称实时生成无限世界。

## 检查与构建

```powershell
npm run check
npm test
npm run build
```

新增 11 项规则测试，验证新世界轮换、身份权限、全部任务可达、确定性后果与刷新回访。原测试覆盖连续开门、同场景内容轮换、所有故事分支与后续、可解布局、旧版手记迁移，以及保留的 3D 候车亭。`dist/` 同时生成 `index.html`、`seaside.html`、`research.html` 与 `worlds.html`。实际浏览器结果见 [验证记录](../VERIFICATION.md)。开发时可用 `?review=1` 将检查过程写入独立手记；研究页也会将这一检查参数传入当前原型的试玩 iframe。此隔离入口仅在 Vite 开发模式生效，正式体验地址不带参数。
