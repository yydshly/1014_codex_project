# Agent 小屋 Web

Three.js + Vite 前端，以及在开发 / 预览服务器内运行的本地 MiniMax 代理。静态构建支持预设协作；真实 Agent 和动态语音依赖本地服务。

## 理解摘要与 Pages 发布

`research.html#synthesis` 解释来源能力、独立实现原理、探索过程、效果、能力与后续方向；引导图直接使用 `../assets/understanding-overview/agent-studio-understanding.png`，不重新生成。`index.html?view=workspace` 与 `?view=room` 保留工作室及原房间。

从仓库根执行 `node projects/003-lofi-room/web/build.mjs`，安装缺失依赖、语法检查、原功能测试和接管/公开模式测试，再以 `LOFI_PAGES_BUILD=1` 构建到 `.cache/pages-dist/`。它与本地 `dist/` 分开，保留已有真实预览。`scripts/build_pages.mjs` 按 `web/pages.json` 的输出目录汇总完整站点，保留所有已发布项目。公开包包含静态页面、已有音频、引导图和选定实测证据，不包含服务器、环境文件、依赖或执行缓存。`publication.json` 保存文件摘要、静态模式及引导图原始 SHA256。

Pages 版强制预设模式，跳过真实后台状态轮询；真实任务入口引导至本地运行说明。目标/演示记录仍保存在当前浏览器。实时 MiniMax、动态对话、编码执行与接管需启动下面的本地服务。GitHub Actions Secrets 可向工作流提供 `MINIMAX_API_KEY` 做语音预生成或验证；它不会给 Pages 提供常驻 API。不能将该密钥放进 `VITE_*` 或公开产物。本次部署无需上传或配置密钥。

官方依据：[Pages 静态托管](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)、[Actions Secrets](https://docs.github.com/en/actions/how-tos/write-workflows/choose-what-workflows-do/use-secrets)。未来如部署受保护的 Node 后台，应在后台配置密钥和权限，再接入在线前端。

## 执行中接管角色（2026-10-20）

点击人物、姓名或头像进入角色工作台，查看实际读取/写入的代码片段、前后差异、命令及实时输出。代码页优先显示最近一次写入的差异，执行命令页按角色保留命令、退出码与失败记录。历史步骤可回看；回到最新步骤后才能控制当前执行。

正在执行的「运行原仓库」后台任务可以点击「暂停执行并接管」。这是执行器的工具边界控制，与原来的「暂停回放」分开：已经开始的命令/页面操作正常收尾，新工具被拦住；并行操作全部收尾后显示「执行已暂停」。为保持开发、审阅、验证产物一致，团队后续步骤一起等待。已发出的模型响应可能收尾，但恢复前不执行它生成的后续工具。

暂停后填写「本轮修改意见」，点击「提交修改意见」，工作台收起并回到房间。角色读取实际代码、命令、原需求和前轮意见，使用 MiniMax 生成回应与调整草案；涉及伙伴接口或验收时，邀请相关伙伴到白板讨论，再吸收建议形成最终方案。本人、伙伴、本人依次发言，实际语音能量驱动口型，白板展示同一版本的意见、负责人、修改对象和验证方法。方案不执行源码或命令，也不代表修改完成。

方案准备好后，点击现场「按方案继续」或工作台「继续同一任务」，人物才离开白板返回原工作位置。讨论中、讨论失败时继续按钮不可用，失败可「重试讨论」；声音受浏览器限制时点击「播放回应」，仍可查看字幕。有未提交文本时禁止直接继续，避免丢失意见。任务编号、源码执行编号、独立目录与已有产物保持不变，不重新克隆或重新下发。意见、方案和对话按版本保存、通过原凭据过滤器脱敏；过期版本请求返回冲突，不覆盖较新的意见。刷新/关页不会自动继续暂停中的任务，也不会自动重播已存的语音；新收到的回应仍正常展示。显式「停止」可取消暂停等待，保存实际记录。

每位后续角色读取本轮接管意见。模型生成旧工具调用期间若收到修改，该旧调用不执行；下一模型步骤读取最新指导，再核对源码。修改发生于审阅/测试阶段时，旧开发或验证结果不能直接交付，回到开发后重新审阅、构建测试与浏览器验收；交付最终封存后不能再接管。原目标、验收用例和测试保护仍生效，意见用于调整实现；更改原验收契约应另开一轮。模型执行时限不计使用者暂停时间，Demo原有有效期仍保留。

房间里，接管角色与协调员走到白板前听取指导，其余任务角色等待，日常伙伴仍可休整；实体电脑显示执行暂停并停止编码光标动效。继续后返回当前任务工位，后续工具事件驱动继续工作。执行状态标识和任务卡均明确显示正在暂停/已暂停。预设演示、离线生成、已结束任务和历史步骤不会显示可用的执行接管按钮。当前支持提出指导与观察代码，不提供任意终端输入或直接编辑宿主工程。

接口：`POST api/tasks/<任务UUID>/pause`、`feedback`、`discuss`（失败重试）、`resume`；均携带角色 `actor` 与修改版本 `version`，feedback另带 `text`（1–2000字，本轮最多20条）。状态、方案和版本通过原任务快照和有序 `execution.control` 事件恢复。重启执行服务仍会将未完成轮次标为中断，不承诺跨服务崩溃自动续跑命令。工作室URL可携带 `task=<后台任务UUID>` 接回指定记录（正在运行的任务优先）；不会重新下发，接回后在当前入口保存原目标与交付。

回归可执行 `npm run test:takeover`（含角色身份、意见版本、语音队列和场景衔接）；模型在生成旧操作时收到意见的边界另见 `tests/source-project.test.js`。真实接管验证记录与截图见 [角色接管证据](../assets/role-takeover/README.md)，语音回应、伙伴讨论、白板方案及同任务交付见 [语音接管实测](../assets/takeover-voice/README.md)。

## 浏览器功能验收与自动返工（2026-10-20）

「运行原仓库」现有闭环增加了强制浏览器验收。桃桃先运行原构建、测试、测试保护及HTTP检查，再在独立、无用户登录态的Chromium中打开本轮Demo。她读取真实页面控件和原始需求，逐条生成带编号的操作用例；每个页面用例都有实际点击/输入及结果断言，不能用页面标题或HTTP200代替功能效果。非UI的原构建、测试、测试保护和HTTP条目使用对应的执行器证据。

首轮用例落盘后固定，返工原样重跑。浏览器记录每步操作、预期、实际、截图、控制台错误与需求编号，断言失败或页面异常均使验证产物退回开发员。原有当面交流、白板讨论、修改、独立重测继续使用同一目标；最多返工三次，仍失败则停止并保存证据。浏览器未通过时记录员不能交付。自动操作验收通过后仍保留用户最终人工体验验收，不自动勾选。

冻结前先核对真实控件类型、select选项值、已访问URL和用例入口。每条原验收对应一个完整独立场景，每个场景自行打开所需弹窗，不继承初探或其它用例的存储与页面状态。源码目录不能充当页面URL；完全相等与包含匹配使用明确的比较字段，按钮状态使用独立的启用/禁用断言。无效用例退回验证员规划；浏览器或规划准备失败则保留记录并中断，不交给开发员盲目修改。执行阶段发现结果不符才进入功能返工。

角色已执行必要工具但未正确提交交接时，可在独立的结果提交步骤中依据已有读取、差异和配置收束计划、研究、开发或审阅产物；不补做源码写入、不伪造命令和浏览器结果，并保留审阅员的需修改结论。验证员观察后未提交计划也可依据同一原需求、真实入口、初探步骤和DOM重新整理计划，之后仍须实际执行。交接恢复不是验收通过的替代品。

在房间选择桃桃并进入工作台，可以查看实际浏览器截图与逐步结果；她面前的实体电脑也显示同一截图、操作与PASS/FAIL。正在执行、历史记录和预设展示分别标记；截图来自执行器，不用示意动画代替实际结果。刷新恢复沿用后台事件与原任务编号。

真实缺陷验证可在任务上下文设置 `verifyCurrentFirst: true`：首轮开发阶段只安装原版依赖、保持源码不变，使用已有Demo入口交给桃桃复现。浏览器实际失败后，桃桃和小蓝分别调用模型讨论复现证据与修复计划，第二位读取第一位发言；对话事件归入同一任务，后续开发员同时收到原用例、失败值及公开讨论记录，再修改源码。每轮浏览器功能失败都会触发这次讨论；没有失败不人为制造返工。缺少已有Demo入口会明确停止，需要研究阶段先准备入口。对话失败不会伪装为已经讨论完成。该选项目前由本机任务接口使用。

已实际运行本仓库的「未保存新目标草稿仍可归档旧目标」缺陷任务：原版浏览器断言失败后触发真实模型对话，首次修改漏导入导致页面报错，再次返工后浏览器通过。审阅模型因误读既有代码中断，随后从检查点续跑，保留同一用例、旧截图与原始来源；本轮仍重新运行原构建、77项原测试、4项新增测试及浏览器操作，并由审阅员独立批准后交付。三项场景的最后28步全部通过；执行器与规划错误、主动取消及误判均保留，详见 [真实任务验证记录](../assets/real-browser-repair/verification.json)。模型交付的三个相关文件已同步回当前工程，文件摘要见同目录 `applied-source.json`。

检查点续跑只在目标与逐条验收完全一致时继承冻结用例和历史截图，并保留原始运行编号。入口路径及查询参数也随用例冻结，避免把工作室误启动成夜半小屋；历史通过结果不替代新一轮验证。布尔断言明确解析 `checked` 和字符串true/false，矛盾值会拒绝，防止把禁用误按默认启用检查。并行审阅若与实际通过的浏览器结果冲突，会把同轮证据交回审阅员复核；不会直接改写其结论。

交付后，房间工具栏的「回看真实返工」根据实际事件、公开模型发言、源码写入及截图重现这次过程，明确标注「真实记录回放 · 不执行新任务」。读入续跑前的原始记录，电脑也按相同历史时刻呈现内容；回看不调用编码工具，不新建任务、不更改人工验收或交付历史。可随时「结束回看」。当前仅回看已经形成失败、双人讨论、源码修改、同用例通过及最终交付的完整记录。实时工具输出不再占满人物动作队列，返工节点优先展示。回归：`node --test tests/repair-replay.test.js`。

首次在本机执行 `npm run browser:install` 安装官方Chromium；`npm run test:browser` 运行真实浏览器回归。缺少浏览器或验收规划失败会如实失败，不退化为只检查HTTP。浏览器仅访问本轮Demo源，不加载个人浏览器资料，不提供任意JavaScript、终端或外部站点工具；它只检查所列DOM交互用例，不代表像素级视觉检查、画布内所有三维动作或所有业务路径均已覆盖。目录执行仍使用当前用户权限。

证据保存在 `.cache/source-runs/<UUID>/browser-plan.json`、`browser.json` 与 `browser/*.jpg`，包含首次失败和后续通过记录；交付ZIP附带相同JSON与截图。新增接口：`GET api/source/runs/<UUID>/browser` 查看验收记录，`GET api/source/runs/<UUID>/browser/<截图UUID>.jpg` 查看实际截图。旧交付不会被重新标为已经完成浏览器验收。

## 后台持续执行与刷新重连（2026-10-20）

从房间下发的真实项目任务和真实方案协作由后台任务管理器持有。提交后立即返回任务编号，同一提交编号重复请求只会接回原任务。关闭页面、刷新、离开房间和暂停回放不会取消后台执行；只有「停止」会发送取消请求并等待后台终态。语音解锁和人物走到工位不再阻塞真实工具执行。

每轮元数据和带连续序号的事件保存在 `.cache/background-tasks/<任务UUID>/task.json` 与 `events.ndjson`，不写入 API 密钥。重新进入时自动找到正在执行的任务；若离开期间已完成，则补回本轮产物与最终状态。原浏览器目标编号、轮次编号和执行目录编号继续关联，已有历史不会被重新生成。观察连接短暂失败时以事件游标重连、去重补齐，不重新提交模型任务。

恢复人物时直接回到当前工作阶段，不从头播完所有历史对白。前端仍按事件展示现场动作；积压过多、绘图异常或后台已结束时会接回当前状态，不能因人物卡住而让执行器永久等待。暂停只冻结房间回放，右上角仍显示真实后台状态与任务编号。

**本地 Node 服务需要保持运行。** 本轮实现覆盖浏览器刷新、关页与临时观察断连，不承诺服务进程崩溃后自动续跑外部命令。服务重启后，未完成轮次明确标为中断，保留源码、草稿和事件；不会悄悄重跑安装、修改或模型调用。已完成轮次仍可读取，已交付 Demo 可按原入口重启。

`npm run test:background` 覆盖持久化事件、断开观察、游标重连、重复提交、显式停止、终态恢复、密钥过滤、浏览器请求绑定、语音解锁和暂停语义；人物快照恢复另见场景编排测试。旧 NDJSON 接口继续兼容原来的连接生命周期，当前房间已改用下面的任务接口。

实测使用本仓库003工作区快照下发两轮 MiniMax 任务：第一轮刷新、离开房间后仍有真实工具记录，主动停止后标为取消；第二轮刷新接回同一任务，暂停观察时后台继续，最终原项目构建、68项测试与 Demo HTTP 检查通过。当前实现的主测试及背景任务、道具、避碰、工作台、屏幕、模板专项共125项通过，构建通过。完整任务编号、原始事件、交付源码和验收边界见 [后台任务验证记录](../assets/background-task/verification.json)。第二轮自动检查7/7通过，但人工验收保持未勾选；检查源码发现模型改动的文案位置没有完整命中原问题，不能据此宣称功能验收通过。

## 从任务到成果的同一条主线（2026-10-20）

工作室右上角常驻「真实任务执行状态」：绿色表示后台真实请求仍在执行，并显示任务内容；黄色表示预设流程演示；灰色表示当前无真实任务。已完成任务、人物日常动作、语音回放和重启已有成果都不会被标成真实开发执行。状态接口每两秒同步一次，断连显示「无法确认」；暂停人物回放时，仍以后台是否在执行为准。完成、异常或取消后清除后台执行标识。该状态来自当前本地服务，可识别同一服务其他页面提交的真实任务。

进入工作室后，常驻任务卡展示当前目标的需求、仓库、轮次、五个执行阶段、实际工具进展和当前处理人物。点击「＋新任务」，填写任务名称、公开 GitHub 地址、具体功能与逐条验收要求，再交给团队。此前的目标与每轮产物仍在「任务记录」中。

交付后从同一任务卡进入「体验成果与验收」：原任务、实际改动摘要、构建测试证据与可操作网页在一个成果页中；自动检查通过不会自动勾选用户的功能验收。逐项核对后可确认完成，或把体验反馈交回团队，在同一目标下开始下一轮。原仓库方式会固定上一轮 commit，从校验过的交付 ZIP 继承实际源码与 Demo 配置，再按反馈修改并重新构建测试；历史轮次、原有测试和 build/test 脚本保持受保护。

本机成果地址到期后可点击「启动已交付的成果」。服务端核对当前源码与已通过验证的摘要后启动已有目录，不调用模型、不伪造新测试结论，更新运行地址和交付包中的服务信息；源码变化则要求重新验证。静态原项目成果仅允许本机工作室嵌入，框架自带禁止内嵌策略时仍可独立窗口打开。每次服务启动最长40分钟，记录与源码保留。

本轮验收：61项回归覆盖目标/需求匹配、反馈关联、源码继承与原测试保护、重启时摘要校验和原验证日志保留；浏览器实际验证了已有 mitt 成果从到期状态重启，在任务内嵌页面订阅和发送并收到回调。本轮没有另起一次 MiniMax 全程开发任务；上一轮真实开发证据继续保留。

## GitHub 项目真实任务闭环（2026-10-19）

### 原仓库方式：配置及执行范围

可选Docker方式：设置 `LOFI_SANDBOX_PROVIDER=docker`，安装并启动 Docker Desktop Linux引擎。执行器拉取官方 `node:22-bookworm`。不挂载宿主目录或Docker socket，非root、只读根文件系统、去除capabilities，限制2CPU、2GB内存和256进程。下载阶段临时联网，之后仅保留内部网络，端口限本机。此适配尚未进行实机端到端验收。

沿用现有 MiniMax 配置即可。默认 `local`；显式设为 `auto` 时仍优先Docker、其次云凭据。`vercel`适配尚未实机验收。更改进程环境变量时需重启服务。

## 协作与房间操作

1. 选择预设流程或真实 Agent，填写目标，点击「开始协作」。预设流程固定演示一次返工；真实流程根据角色检查结果决定是否返工，最多一轮。
2. 默认收起侧栏，让人物推动过程：白板前集结、到工位操作、电脑椅侧入座打字、当面交流与递交、白板前汇报。审阅员与验证员同时到各自工位。快速返回的模型结果也会等人物到位，并至少工作四秒，再展示产物。
3. 「暂停回放」冻结走动、工作计时、交接与播报；真实模型在服务端可能继续生成。「停止」取消本轮请求和动作等待，清理播报与待处理事件，保留已有产物。临时讨论期间，原交接与回放计时保持暂停；继续时先返回工位，再恢复播报。
4. 点产物打开全文；点人物查看任务、试听音色和进入其视角；「导出」保存本轮 JSON。
5. 自由观察：拖动旋转、滚轮 / 双指缩放；「关注发言者」让视角跟随工作区域，拖动后停止自动跟随。漫游：WASD / 方向键移动、Shift 跑步、拖动环顾、Esc 返回。工作室采用独立观察者，人物持续工作；原房间保留从所选住客视角出发。手机提供方向按钮与任务面板入口。

语音失败时展示原因并保留字幕；不会替换成浏览器系统语音。角色模型失败时终止并保留产物，不会伪装成预设流程成功。页面切到后台时自动暂停回放。

分工播报结束后，无关人员离开白板。`HOME_SPOTS` 定义个人活动：整理笔记、电脑资料、写手记、地垫阅读、沙发阅读与休息。交接只召集双方，完成后短暂停留以衔接下一项任务；没有新任务就回自己的位置。整轮交付后六人散场。个人活动独立于任务状态，不会产生虚假进度；临时讨论期间，未参与且正在休息的人可以继续自己的活动，已暂停的任务操作保持冻结。暂停和停止仍同时控制这些人物动作。

「真实 Agent · MiniMax 模型」保留原有方案讨论模式，仅生成文字方案；「真实项目」另提供上述读仓库、写文件和隔离测试工具。预设模式不执行真实开发任务。

待命活动由 `ambient-life.js` 编排：每个人先在个人位置停留，再错开喝水、站立伸展或短距离慢走；活动后回原位置停留 25–53 秒。最多两人同时离开个人位置，饮水角独占，路径继续避开家具。喝水包含伸手拿杯、举杯、轻微倾杯和放回；任务或讨论优先打断活动，持杯者先放杯再走。活动计时跟随场景暂停；减少动态效果时只回个人位置，不再自动走动和伸展。

`room-social.js` 在此基础上编排两人互动：慢走路过空闲伙伴时暂停路线、挥手招呼和回应；休息时选择空闲且最近未交谈的伙伴，近处原地聊，远处走近后再聊。对话只占用这两人，结束后恢复原路线、坐姿或个人活动；同一对人物有冷却间隔。工作、用户发起的讨论、停止与减少动态效果可以取消闲聊，不会保留过期话音。

人物语音使用单一发言权：主任务播报、工作核对、闲聊与用户讨论不会叠音。页面下方的「开启房间语音」提供浏览器需要的首次播放手势，之后可随时关闭；「角色语音」控制全部角色播报。暂停会同时冻结对话计时、声音和人物；工作回应被手动讨论打断时保留原话，回到原位置后继续。首次未开启声音时仍展示字幕。

接收交接后，人物会语音确认；开发员和记录员开工前主动与实际输入的提交者核对。预设模式播放准备好的工作短句；真实模式读取该轮交接的任务、产物标题和摘要，实时合成两人的对齐发言。此处复用已有产物，不额外调用文本模型生成新结论。

`public/voices/room/` 的 36 段短句已随构建提供，来源见其 `manifest.json`。`npm run room-voices` 按 `shared/room-lines.js` 生成缺失录音，需要 MiniMax 配置且产生语音服务调用；已存在的文件跳过，短暂限流会有限重试。

## 道具与观察修正（2026-10-20）

手持书本与笔记按读者方向排版，同一实体在手中与停放位置切换。只有角色实际阅读才自动翻页；闲置书合上，点击「打开读本」后才允许用户手动翻阅，并标明所在位置与用途。翻页采用当前右页/下一章左页的正反面纹理，手部随翻页移动。近景采用读者视角，可拖动旁观并恢复跟随；支持关闭自动翻页及展开正文文本，阅读文字时停止自动翻页。观察期间暂缓该角色自主休息和新闲聊，实际工作仍可打断；退出后恢复日常活动。全景工具栏分行排布，任务卡详情可收起。完整问题、截图、修正及验证边界见 [道具审查记录](../PROP_AUDIT.md)。

## 代码结构

工作室支持直接观察角色的工作平台：点击人物或房间上方的角色选择器，进入对应的任务白板、研究台、开发电脑、审阅台、测试终端和交付台。锁定角色后，并行伙伴的活动不会抢走视角；开启「跟随任务步骤」会按真实工具活动切换负责人。底部步骤可回看，点击「回到最新步骤」恢复最新记录；「向他提问」接入原有目标讨论。

原项目执行器通过 `work.activity` 事件发送实际命令、退出码、分段输出、读取的源码片段和写入前后的变化区域。开发电脑和测试笔记本分别显示小蓝、桃桃的内容，包含执行光标、活动条、源码回显和成功/失败状态；这些动画不生成额外的执行结果。工作台即时接收执行证据，人物行走和语音独立排队；后台任务持续执行，重连时人物追上当前工作阶段。旧流式入口保留到岗确认。历史记录和预设演示有明确标签，页面展示公开产物与工具记录，不展示模型的内部思维过程。

观察功能回归：`node --test tests/workbench.test.js tests/workbench-stream.test.js`。其中一项运行真实子进程并验证退出前已收到输出，一项验证人物交接等待不阻塞执行记录接收；这些测试不代表一次新的 MiniMax 任务已经交付。

六位角色的日常道具也带有内容。各自的原创读本分别围绕目标协调、资料研究、源码修改、审阅、测试和交付归档，阅读时呈现双页正文、摘记、页码与翻页。个人笔记显示当前目标、自己的最新产物摘录与验收提醒；没有产物时明确标为日常笔记。写字时文字逐步增加，长笔记可分页阅读，笔记本留在桌面。六只杯子有角色颜色、姓名、杯内水面与涟漪，从各自杯位取放，实际喝水时水量下降，放回后不凭空补水。点击实体书本、笔记或杯子，或在角色观察栏选择「随身物品」，可切换角色、读本/笔记/水杯并翻页；返回全景或按 Esc 退出。日常内容与动作不会生成任务产物或推进执行状态。回归：`npm run test:props`。

阅读采用连续动作：走到取书点、俯身伸手、接触书缘后抬起、合书携带、到阅读位置坐稳再打开。新任务到来时，先合书，拿回原桌面，接触桌面后松手、收回手臂，再走向工位；到岗确认不会被中间取放位置提前触发。暂停冻结人物、书本和页数；途中改派保留最新目标，停止不会把手里的书瞬移回桌面。沙发重新匹配坐垫高度与腿长，先转向再后退入座，起身先将臀部移向脚部支撑点，再走出。物品面板的「观察人物动作」可跟随全过程；「去拿书阅读／收书回工位」是独立动作预览，任务执行或讨论期间禁用，不调用模型、不修改任务记录。

房间内的电脑也直接呈现工作内容：开发显示器采用编辑器布局，包含行号、源码着色、当前行、光标和独立终端；验证员的笔记本显示真实命令及测试输出。源码写入时逐字回显，键盘按键与屏幕微光随活动变化。点击实体屏幕、角色观察栏的「电脑近景」或「协作电脑」，相机会靠近对应电脑；底部可切换开发/测试屏幕、查看工作台或返回全景，Esc也可返回。历史默认静止，「回放屏幕动效」明确标注记录回放；没有真实数据时使用标明用途的示意代码，不下发任务或生成测试通过结果。减少动态效果时停用逐字与按键动画。回归：`npm run test:screens`。

人物之间采用动态碰撞与绕行：在通道内接近伙伴时绕开，必要时侧移让路，随后继续原任务；头顶说明会显示等待或让路。入座和离座只允许经过自己的座位，仍检查其他人和家具。第一人称漫游与住客双向碰撞，临时白板站位避开固定工作人员和预留位置。书本转向读者后同步转换左右抓取点，合书居中携带，肘部从身体外侧弯曲。回归：`npm run test:traffic`；复现指标与边界见 [人物穿模排查](../COLLISION_AUDIT.md)。

薄地毯、流苏与厚坐垫共用地面支撑定义：行走绕开厚坐垫，脚部按整只鞋的实际体积检查高度，包含侧步、入座和起身。地垫阅读双脚支撑在前方，收腿起身前先抬脚；沙发底框为脚跟留出空间。回归：`npm run test:ground`，不会调用任务模型或语音。

脚部采用交替支撑：落脚后固定世界位置，另一只脚抬起、迈出、落地；停止、转身和侧向让路后依次收脚站稳。身体高度配合腿长和支撑面调整，地垫起身两脚依次收回后才抬起髋部，办公椅与沙发先准备支撑再坐下。检查同时约束贴地高度和支撑脚位移，覆盖慢走、快走及低帧率。数值复验：`node scripts/audit-foot-support.mjs`。
