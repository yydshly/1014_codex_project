## 研究问题

1. 一个陌生代码库能否被整理为准确、可读的结构图，而不是只有漂亮的节点和箭头？
2. 图中的关键组件和连接能否对应固定版本源码，方便读者检查？
3. 生成后的 HTML 能否在本仓库的 GitHub Pages 子路径正常显示、交互与导出？
4. 这类图解能否帮助开源维护者解释项目、帮助新人理解代码？

首轮只研究一个代码库的结构与一条调用路径，控制功能范围。

### 实际复现：2026-10-14

- 研究对象：Archify 自身固定版本的 `render architecture` 分支。
- 上游缓存：`web/.cache/upstream`，通过浅克隆固定在上述 commit，源码未修改。
- 环境：Windows NTFS；实际通过的运行环境为 Node.js `v24.19.0`；独立浏览器检查使用本机 Chrome。
- 输入：`web/data/project.mjs`，导出中文与英文 JSON；来源定位覆盖共用加载器、命令入口、架构渲染器、写入模块与浏览器阅读器。
- 输出：`web/dist/diagrams/archify-zh.html` 和 `archify-en.html`，由上游原生代码生成，网页外壳不伪造原生图解。
- 本地服务：`http://127.0.0.1:4173/1014_codex_project/001-archify/`；仅绑定本机回环地址，未发布。

复现中解决的问题：

1. 系统 Node.js `v22.15.0` 在本机同一文件上返回的 `lstat.dev` 为 `0`，`fstat.dev` 为 `385317404`，导致上游文件身份校验失败。使用已有的 Node.js `v24.19.0` 后两者一致并通过。未关闭校验、未修改上游、未更新系统 Node.js。这是本机实测结果，不推断所有 Windows 或所有旧版 Node.js 都会失败。
2. 首个输入引用了不存在的源文件末行 `1205`，上游明确拒绝生成。核对固定版本实际 EOF 后改为 `1204`，说明来源校验能拒绝越界引用。
3. 初始 iframe 高度低于原生图解内容高度，出现额外内部滚动；调整桌面容器高度后完整显示图解。

## 实现分析

根据上游说明，待复现的主流程为：代理分析描述或代码 → 生成图解 JSON → 渲染与校验 → 输出交互式 HTML。

必须区分两种能力：静态网站展示已有图解；根据任意新输入自动生成图解还需要代理或模型调用。GitHub Pages 本身不提供后者。

优先阅读固定版本的以下文件与目录：

- [运行清单](https://github.com/tt-a1i/archify/blob/1c2b42d660e4a7571813fb43839c79e3e9ca7720/archify/package.json)
- [命令行入口](https://github.com/tt-a1i/archify/blob/1c2b42d660e4a7571813fb43839c79e3e9ca7720/archify/bin/archify.mjs)
- [示例输出](https://github.com/tt-a1i/archify/blob/1c2b42d660e4a7571813fb43839c79e3e9ca7720/examples/web-app.html)

已追踪的核心关系：命令入口选择渲染器；共用加载器读取 JSON 并核验格式与来源；架构渲染器检查布局并生成 SVG；输出模块填充阅读器模板并写入独立 HTML；浏览器基于已声明节点与有向连接提供探索。图中不包含未核验的在线 AI 服务、账户或后台。

自动格式与来源检查不会证明图解的语义一定正确。组件含义和关系仍由研究者阅读源码后整理；付费需求仍未验证。

出海方向假设：**面向开源项目的交互式代码库导览**。目标用户为需要解释项目的维护者、技术写作者及需要了解系统的小团队。

可探索的增值功能包括固定源码链接、英文图解模板、版本变更对照，以及团队入门资料。先用一个真实项目验证准确性和阅读价值；高级功能与付费模式暂不实施。

初步需求验证：让 3–5 位目标读者分别使用 README 和图解完成同一组理解问题，记录回答是否准确、定位信息是否更快、是否会再次使用或分享。免费工具已有竞争，付费价值必须来自具体工作收益。
