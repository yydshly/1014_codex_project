# 实施设计与任务拆分

v0.1 已实现资料导入、证据台、B/C 对照、报告复核与导出。未实现 A 联网、人设模拟、真人留出和收费验证。具体命令和导入格式见 [web/README.md](web/README.md)。下方未注明已完成的扩展仍是计划。

## 技术选择

实际实现采用仓库 009 已使用的 Node.js ES modules + 本机 Codex CLI 接入方式，使用 Node 内置 SQLite 持久化资料与证据，私有运行目录保存冻结原文和调用日志。静态 HTML/CSS/JS 提供中文工作台，单操作者本机运行，无第三方 npm 依赖。

原候选为 TypeScript + eve；检查发现当前 eve 0.79.1 要求 Node ≥24，而本机为 22.15。当前需求为受控的三次文本调用，不需要长驻代理工具或渠道，沿用已存在的接入栈，未引入未使用的框架或新密钥。以后需要持久会话再评估迁移。CLI 选项已核对本机 0.162.0-alpha.17.2 的帮助及官方文档；请求模型显式固定为 gpt-6.1-sol，推理强度 medium。服务方不可变快照与美元计价不可观测，不能声称已锁定。

评测器与研究服务分离：只有评测器可读留出答案。将来静态 GitHub Pages 可展示去标识报告，动态模型服务、私有数据与密钥须独立承载；当前未部署。

## 业务工具草案

- import_source：登记有使用权的资料；只有 URL 不能成为已读引用。
- get_source_span：读指定区段，返回定位和哈希。
- list_evidence：按问题、来源簇、证据类型取卡片。
- compare_alternatives：整理官方说明与用户经历，保留冲突。
- create_persona：只用可见证据，未知保持未知。
- simulate_response：输入原型/固定候选/问题，返回 simulated 假设。
- validate_report：检查结构、引用存在性、模拟隔离；语义仍需人工。
- export_report：本地导出并记录局限、成本和未完成步骤。

上述是接口名称草案，不是 eve 内置函数。首版按顺序执行，不需要多代理并发、自动外发或长期监控。

## 输入与访问边界

网页和访谈是待分析的数据，不执行其中的指令。模型不能凭资料文字扩展权限、读取密钥或联系第三方。网络工具只访问来源 allowlist；私有正文不拼入外站搜索词或 URL。

应用端检查来源、预算和字段；不只靠提示词。模拟 ID 不能作为事实 evidence_id。语法与引用存在性可自动检查，事实支持仍由人工复核。

## 成本与审计

调用记录阶段、精确模型、输入/输出/推理 token、计价版本、费用、耗时、缓存、重试和可见来源。原始资料与提交给模型的内容分别管理。

运行器调用前检查正文和提示词字节数、调用次数，按每次超时取消。用量超限在返回后判为 failed；CLI 无可强制的费用/token 硬上限，界面和运行说明明确披露，不能把它说成预付费上限。无效引文的发现进入拒绝队列，报告为 partial。人的获取/配置/复核成本未测量。

## 实施顺序与验收

1. 资料底座：导入、原文定位、去重和删除传播。一条证据能回到原文，同一事件不重复算来源。
2. B/C 对照：统一报告、直接分析、结构化反证和成本记录；底层语料哈希必须一致。
3. A 对照：接搜索和读取，完整记录覆盖、失败和人的时间。
4. 真人留出：同意、F1/F2 分割、独立评测权限；未完成不能宣称预测更准。
5. 可选模拟：冻结 D 的原型问题与预算，比较 D/C；没有增益就停用。
6. 第二批验证与收费试点：新问题、真实交付、真实成本和付款记录。

已验证相同语料与人工笔记隔离、来源去重、虚构引文拒绝、用量超额中止、取消、撤回传播、HTTP 导入到导出，并实际用本机模型跑完 B/C。浏览器发现并修复证据保存后的刷新错误。留出答案隔离属于未来真人评测，不把当前测试视为已完成留出研究；独立的硬超时由模型适配器执行，尚无专门的进程超时故障注入测试。
