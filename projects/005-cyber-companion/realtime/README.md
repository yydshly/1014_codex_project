# 实时真人闭环：能力检查与验证状态

日期：2026-10-15。

目标：同一个真人形象持续待机，接收输入后说话，能够被打断，然后恢复倾听并回应新的问题。预生成视频与 Live2D 控制测试不作为此目标通过的证据。

## 当前阻塞

用户已确认暂时没有数字人相关的线上能力；同时要求暂不下载新模型。仓库现有配置只发现 MiniMax，未发现实时数字人服务凭据，相关进程环境变量也未配置。

因此本轮不能建立真实人物音视频会话，不能验证真人闭环。没有创建新的服务账号、升级套餐、下载模型权重、安装 CUDA / PyTorch 环境，或启用摄像头和麦克风。

| 环节 | 当前能力与证据 | 真人目标状态 |
| --- | --- | --- |
| 回复文字 | 既有 MiniMax-M3 已成功流式调用 | 可复用；未证明能接入实时数字人 |

| 恢复倾听 | 未采集真实麦克风输入并验证人物对新问题作答 | 未验证 |

## 后续接入的最小验证顺序

以下是验收标准，没有执行成功的记录：

1. 建立一个真实在线会话，收到持续人物画面。观察至少十秒，记录人物身份、视线、呼吸和细微动作；仅收到视频帧不足以判定自然待机合格。
2. 通过实际输入触发一段足够长的中文回复，核对声音、嘴型、表情和动作是否一致，记录首声及首个说话画面的延迟。
3. 人物仍在说话时发送一次远端打断。保持远端声音可听，测量真实停止发声的延迟；不以静音播放器或本地按钮状态代替远端打断成功。
4. 保持会话与人物画面连续，用户说一个新问题，确认人物回答的是新问题。仅恢复麦克风发布或显示「倾听中」不足以验收。
5. 重复三轮，并结束会话、释放媒体和远端连接。记录失败、尾音、旧回复串入或人物跳变。

## 已核对的接口线索

Vidu S2 官方 Node 示例使用 HTTP 创建会话、WebSocket 控制和 AliRTC 实时音视频。其协议说明包含 `type: 7` 打断当前 AI 输出，且没有独立业务确认回执。发送该指令只能证明发出控制请求，仍需通过实际媒体观察判断成功。

本轮仅阅读接口与示例，没有可用账号进行调用。未证明 Vidu 可直接接受当前 MiniMax 语音输出，也未实测其人物自然程度、延迟和打断效果。
