# 011 · 古人说唱 Battle：AI 视频制作流程研究

用一份中文交互网页，说明 [ancient-rap-battle](https://github.com/10291124jcjc-dotcom/ancient-rap-battle) 能做什么、价值在哪里，以及怎样复现或搭建类似流程。

这个上游项目是一套 **Claude Code Skill、创作模板和 Python 脚本**：把历史人物选题、说唱歌曲、角色参考图、逐句视频生成、质检与后期连接起来。它的核心价值是把一条容易反复返工的视频制作过程，拆成可以检查、替换和局部重做的步骤。

## 网页里可以看什么

- **当前成果汇总**：《压轴人间》新的94.64秒原曲驱动舞台版可直接播放：主角演唱按原曲音频生成，配合舞台、观众及细节；整片效果待用户听看。旧拒收片、《敬风霜》及早期试片继续独立展示。
- **能力和人机分工**：歌词、音乐、定妆、时间轴、分镜、生成、质检、包装分别由谁完成。
- **价值和适用场景**：为何采用逐句素材、反应镜头、统一角色参考和可替换的剪辑时间表。
- **实现原理**：从 `episode.json` 到歌曲时间轴、素材清单、候选版本和最终成片的数据流。
- **复现与类似实现**：原版操作顺序、小规模验证路径，以及自行搭建时需要的数据契约、预算和恢复机制。

上游示例图片和原作视频用于解释目标效果，均标明来源；它们不是本项目调用模型生成的结果。网页内置 HTML 视频播放器，播放从固定版本下载并保留原文件的 `assets/demo-github.mp4`，无需跳转 GitHub；仍保留上游原始链接用于核对。该分享版实测 102.13 秒、960×540、24 fps；制作脚本的 1080p 输出设置不代表此文件为 1080p。

## 主要结论

| 问题 | 研究结论 |
| --- | --- |
| 是一个独立模型吗？ | 是对多个外部服务和本地工具的编排。歌曲由用户在 Suno 生成，8 张参考图由用户在 Midjourney 生成，视频脚本调用 MiniMax H3。 |
| 能完全无人值守吗？ | 原版流程保留歌词确认、选歌、参考图筛选、首条测试、镜头审核和付费确认。 |
| 为什么一句一条？ | 缩短模型需要遵循的声音和动作范围，便于发现漂移、切换候选版本和单句重做。 |
| 自动检查能保证口型吗？ | 不能。`qa.py` 比较生成音轨与输入人声的能量变化，是间接筛查；可选 `lipcheck.py` 估计嘴部开合与声音的时差，也需要人看。 |
| 1080p 是原生生成吗？ | 默认 API 生成分辨率是 768P，后期输出 1920×1080；分辨率放大不等于新增真实细节。 |
| 大约花多少钱？ | 作者记录的 1 分 42 秒示例约花 16 美元视频生成费；脚本内价格是固定版本的估算常量，不能作为现价或总价保证。 |

默认模板是 A 先唱 16 句、B 回应 18 句。34 句歌词中部分位置使用反应和观众镜头，因此产生 **27 条说唱素材 + 8 条过场素材，共 35 条、180 秒待生成素材**；最终成片只使用其中片段。详见 [实现分析](RESEARCH.md)。

## 新成果：压轴人间原曲驱动舞台版

[新完整视频](experiments/004-performance-film/work/audio-driven-repair/full-reedit/final/压轴人间-原曲驱动舞台版.mp4)已导出并接入本地网页 `#repaired-film-004`：94.64秒、1280×720、25fps、2366帧、45,964,902字节，SHA-256为`97a08f79cdeba756fb35280652445343be25219b2cc1ded532e3c62e3ccad4a6`。22个镜头中对应原曲的人物演唱40.96秒、观众20.08秒，其余为动态开场、收尾、舞台和无脸服装细节。没有MV调用、本地生成模型、静图运镜或画面变速。

五条新演唱视频均明确提交锁定人物图、舞台图和对应原曲WAV，按同一歌曲时段剪入；新舞台细节及已有观众/无脸片段独立登记来源。完整原歌不裁切、不变速，仅一次−1.5dB和不足一帧尾静音。全2366帧解码、原曲内容核验、22镜中点与21组切口画面检查完成。用户只验收过原5秒试片，未把该反馈或音频相关性当作整片逐字口型验收；代理没有声称主观听音或浏览器全片播放通过。字幕仍有三条未确认内容省略。

当前账本2265钻已提交、110钻未确认预留、总敞口2375钻，保留在2400钻上限内；615钻为这六条后续任务的官方回报总额，独立账单未核对。[真实合成报告](experiments/004-performance-film/work/audio-driven-repair/full-reedit/reedit-film-report.json)、[实际抽帧审看](experiments/004-performance-film/work/audio-driven-repair/full-reedit/final-editorial-review.json)与[网页记录](web/public/data/004-repaired-film.json)保存来源和边界。旧被拒收视频原字节与原结论保留。

## 本地查看网页

本目录的网页提供原作视频播放、能力整理、流程讲解和参数演示，不会上传素材或发起模型付费请求。原作视频随静态网页构建复制到 `dist/media/`。

需要 Node.js 22 或更新版本，无需安装第三方依赖。

```powershell
cd projects/011-ancient-rap-battle/web
npm run dev
```

打开终端显示的本地地址，默认端口为 `4184`。构建执行 `npm run build`，产物位于 `web/dist/`。发布约定和总服务入口见 [Web 说明](web/README.md) 与 [部署说明](../../docs/DEPLOYMENT.md)；公开演示地址仅在实际发布并验证后登记。

若要运行完整上游视频制作流程，请按 [原版复现步骤](RESEARCH.md#原版复现步骤) 准备账号、环境、歌曲与参考图。本项目独立的小样脚本位于实验目录；网页仅展示已保存的结果，不从页面发起付费请求。
