# 研究归档网页与原实验工具

首页是更新至 2026-10-19 的研究与思考档案：原帖、演进路径、7 个详细专题、26 个问题、34 条来源、23 份材料、实际 B/C 完整报告和停止决定。专题覆盖研究价值、身份记忆、真实数据、娱乐社区、NPC 和玩法、扩展、信息沉淀与行动产品。`/#action-plan` 展示流程与产品规格，材料库可下载历史研究行动样例；这些不是新工作台功能。原实验保持停止，原工具仍在 `/workbench/`；浏览归档不运行模型。

## 仅阅读与保存研究归档

需要 Node.js ≥22.15 进行构建，无第三方依赖，不需要 Codex 登录。运行 `npm run build`，生成的 `dist/index.html` 是包含 CSS、脚本、资料、原始文档和历史截图的单个文件，可离线打开。构建还会根据 `archive/journey.mjs` 和 `archive/content.mjs` 生成上级目录的 `DISCUSSION.md`，请修改结构化源而非手工编辑该生成文件。逐份保留 SHA-256，网页可导出完整 JSON 或 Markdown，新增专题与全部问题也包括在内。

源码在 `archive/`；`scripts/build-archive.mjs` 只读取明确列出的项目公开文件和已审核的合成资料快照，**不读取 `.runtime`、密钥或真实私有资料**。外部网站只保存链接与研究摘要，不镜像第三方全文。静态发布时将此文件放到 `/1014_codex_project/010-evidence-research-lab/index.html`；003 的现有项目首页服务也能读取本项目 `dist/`，无需改它的路由。

## 本机服务与实验工具

本机服务需要 Node.js **22.15 或以上**（使用内置 SQLite）。只有要重新运行实验工具时才需要已登录的 Codex CLI。本项目无第三方 npm 依赖，无需 npm install。

~~~powershell
cd F:\codex_project\1014_codex_project\projects\010-evidence-research-lab\web
codex login status
npm run dev
~~~

打开 [研究归档首页](http://127.0.0.1:4184/)，或 [原 B/C 工具](http://127.0.0.1:4184/workbench/)。同站编号入口 `/1014_codex_project/010-evidence-research-lab/` 显示相同归档。服务启动时先构建归档；仅浏览归档不读取模型状态或调用 API。工具默认请求模型 `gpt-6.1-sol`，推理强度 medium；可复制 [.env.example](.env.example) 为 `.env.local` 配置 `CODEX_MODEL`、`CODEX_BIN`、端口和资料目录。模型名必须在你的账户中可用。换模型前重启服务；一轮内不可换模型。

首次使用：载入合成样例 → 证据台复制原话保存卡片 → B/C 对照填写决策问题并运行 → 看支持/反证及原文 → 人工复核 → 导出。每轮最多三次模型调用，会消耗已登录账户的用量。

## 导入约定

- 粘贴文本：填写标题、正文、来源类型、属性、使用权说明，URL 和同一事件分组可选。
- TXT / Markdown：按 UTF-8 文本读取，每个文件是一份资料，默认类型为用户自述。其他类型建议用粘贴表单或 JSON。二进制 PDF、Word、扫描图暂不支持。
- JSON：支持数组、单份资料，或 `{ "sources": [...] }`。字段见下例；只有 URL 没有正文会被拒绝，不会自动访问 URL。
- 正文统一 NFC 和 LF 换行、去首尾空白；之后所有引文均按规范化正文定位。相同正文只保留一份；相同规范化 URL 或人工事件分组共享一个来源簇。近似转述不能自动识别，需操作者指定同一事件。

~~~json
{
  "sources": [{
    "title": "经同意的访谈摘录",
    "text": "逐字正文。保留已经去标识的必要上下文。",
    "url": "",
    "kind": "user_self_report",
    "origin": "provided",
    "permission_note": "本人访谈，已取得研究使用同意",
    "cluster_key": "interview-a"
  }]
}
~~~

`kind` 可选 `user_self_report` / `vendor_claim` / `observed` / `inferred`；`origin` 是 `provided` 或 `synthetic`。不要把合成资料标为真人。

## 对照约定

| 项目 | B | C |
| --- | --- | --- |
| 原始资料 | 完整冻结正文 | 同一份完整正文，无截断 |
| 额外处理 | 一次直接分析，可自行选择研究策略 | 一次证据提取、校验和去重，再一次分析 |
| 报告接口 | 相同 | 相同 |
| 检索 / 工具 | 禁止 | 禁止 |
| 人工证据卡 | 不参与 | 不参与；重新提取，避免跨组泄漏 |
| 用量 | 本组全部调用 | 提取和分析全部调用 |

顺序随机，三次调用使用独立临时会话、显式相同模型和推理设置。输入 manifest、资料哈希、提示词、schema、原始输出、调用与计量保存在本机。C 的报告模型同时看到原文和其自己生成的证据；B 可自由在一次推理中整理证据。C 的干预是多阶段证据工作流，不能把差异归因为底层模型更强。

报告自动校验 JSON 结构、资料编号、引文逐字存在性和位置；无有效支持引用或含无效引用的发现会被隔离，报告标记 `partial`。引文存在率不衡量语义准确性。全部发现经操作者选择“受到证据支持”后才标为 `completed`；撤销或拒绝复核会回到草稿。空报告不会自动完成。

## 数据与限制

- 数据默认存放 `web/.runtime/lab.sqlite` 和 `.runtime/runs/<id>/`，已忽略，不上传到 GitHub。资料会发给所选模型服务处理，并非离线推理。
- “撤回”会级联删除人工卡片，以及包含此来源的整个实验、原文快照和本地导出副本；浏览器另存的下载文件需自行删除。
- 实验进行中不允许增删来源；可以查看原文与整理人工笔记。失败或取消仍保留阶段及可观测用量；重启后的未完实验标为中断，不伪造恢复成功。
- 单轮资料 JSON ≤36 KB，单次提示 ≤65 KB，每组最多 2 次调用，最终发现 ≤6 条；超限拒绝而非截断正文。每次调用默认 4 分钟，无应用层自动重试。
- CLI 不暴露可强制的输出 token / 美元费用上限。每组返回用量超过 120000 token 会停止并判该轮失败；这是**事后检查**，不是硬消费上限。账户额度仍可能消耗，内部重试不可完整观测。
- 同一模型标识不等于锁死服务方权重。不可变快照、温度、推理 token 细分和美元费用未公开时如实留空；不能据此做严格的快照复现实验或美元效率结论。
- 服务仅绑定回环地址，写接口校验本机来源与会话令牌。模型无工具，检测到工具事件立即终止。当前为个人本机工具，不提供多人认证和公网部署。
