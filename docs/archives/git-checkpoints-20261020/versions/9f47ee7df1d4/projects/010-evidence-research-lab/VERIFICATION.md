## 2026-10-19 · 修复“只有文字、样式未加载”

用户实际反馈只有文字。沿 HTTP 响应检查发现，内联 style 含 1 处 CRLF，旧服务按原始字符计算 CSP 指纹，未覆盖浏览器在 HTML 解析前将 CRLF / CR 规范为 LF 的行为。旧响应对原文指纹返回允许，但对规范化后的样式指纹不允许；这会拦截整段 CSS。[HTML 换行处理标准](https://html.spec.whatwg.org/multipage/parsing.html#preprocessing-the-input-stream)说明该转换。

先将原 HTTP 归档测试改为按 HTML 规范化后的文本核对，修复前实际复现失败，信息为“style 的安全指纹必须匹配 HTML 换行规范化后的内容”。此前测试只检查服务端与原文计算一致，不能证明浏览器会接受样式，这是原验证的遗漏。

修复：server.mjs 通过 lib/csp.mjs 按规范化文本计算样式和脚本指纹；构建时同时将嵌入 CSS / JS 转为 LF，原始材料文件与存档哈希保持不变。没有添加 unsafe-inline 或放宽页面安全策略。增加混合 CRLF / CR、中文脚本的独立回归样例。

16 个脚本语法检查与全部 15 项测试通过（原 9 项流程测试 + 6 项归档与 CSP 测试）。本机服务已重启；对首页和编号路径按浏览器换行规则检查安全指纹，阅读仍不调用模型。浏览器视觉复核限制仍存在，实际用户页面刷新是最终呈现确认；不把 HTTP 或规范化校验冒充浏览器截图。
